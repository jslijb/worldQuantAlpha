# BRAIN 核心数据集类别详解

> 来源：WorldQuant BRAIN 数据集类别教程（价量、基本面、分析师预估、情绪、美国新闻、股票关系）
> 本文档覆盖：各数据集业务含义、字段表、使用注意事项、典型 Alpha 思路。

---

## 一、一句话总结

BRAIN 数据集可分为 **6 大类**：价量（Price/Volume）、基本面（Fundamental）、分析师预估（Analyst Estimate）、情绪（Sentiment）、新闻（News）、关系（Relationship）。
前两类最基础、最常用；新闻和情绪属于事件/另类数据；分析师预估是低频但有效的基本面增强信号。

> ⚠️ **口径说明**：这是**教程的教学分类**。平台 Data Explorer 类别筛选器实际只有 **7 个类别**：analyst / fundamental / model / news / option / pv / socialmedia——sentiment、relationship 不是平台独立类别。涉及金字塔（Pyramid）计数时，以平台 7 类为准。

## 二、股票价格成交量数据（Price/Volume）

### 业务含义

价量数据给出股票每日的开盘、最高、最低、收盘价格以及成交量。

- `open`、`high`、`low`、`close`、`volume`、`vwap`、`sharesout` 已经针对公司行为（股息、拆股、反向拆股等）进行了调整，**可直接用于 Alpha 计算**。
- **原始价格或成交量不能直接用于 Alpha 代码**，否则 Alpha 会不稳定。

### 举例：为什么要调整？

假设 GOOG 在 4 月 2 日进行 2:1 拆股，当前价格 $1200。4 月 3 日价格会变为约 $600。如果不做调整，直接使用原始价格会扭曲价格走势。

### 调整数据的使用规则

- 调整后数据必须每天更新。
- 为提高效率，BRAIN 平台只针对固定回看周期进行计算（即 Simulation Settings 中的 **Lookback Days**）。
- 股息和拆分数据仅在事件发生当天有值，其他日期为缺失（NaN）。与其他每天都有值的数据结合时，必须注意这一点。

### 关键字段解释

| 字段 | 英文原名 | 含义 |
|---|---|---|
| 开盘价 | open | 每日开盘价 |
| 收盘价 | close | 每日收盘价 |
| 最高价 | high | 每日最高价 |
| 最低价 | low | 每日最低价 |
| 成交量加权平均价 | vwap | 当日所有交易美元价值 ÷ 总交易量，从开盘到收盘 |
| 成交量 | volume | 每日成交量 |
| 收益率 | returns | 每日收益率 |
| 20 日平均成交量 | ADV20 | 过去 20 日平均每日成交量 |
| 流通股数 | sharesout | 每日流通在外股份数（百万计） |
| 市值 | market_cap / cap | 每日市值（百万计） |
| 拆分比例 | split | 股票拆分比例 |
| 股息 | dividends | 股息 |
| 市场 | market | 市场分组（整数值） |
| 国家 | country | 国家分组 |
| 交易所 | exchange | 交易所分组 |
| 行业板块 | sector | 行业板块分组 |
| 行业 | industry | 行业分组 |
| 子行业 | subindustry | 子行业分组 |

### 分组字段说明

分组字段为每只股票提供一个整数值，对应其所属组别。例如：若 sector 有 4 个可能取值，则 sector 字段值为 0、1、2 或 3。

**大白话拆解（为什么是 0/1/2/3）**

| 你看到的 | 平台底层实际存的 |
|---|---|
| "苹果属于科技板块" | `sector = 0` |
| "摩根大通属于金融板块" | `sector = 1` |
| "埃克森美孚属于能源板块" | `sector = 2` |
| "辉瑞属于医药板块" | `sector = 3` |

- **含义**：这个市场里 sector 一共只有 4 个不同类别，于是被编成 0、1、2、3 四个整数。类别数决定编号范围，且**从 0 开始排**（3 类 → 0/1/2；11 类 → 0~10）。
- **编号是任意分配的，不是排名**：0 不代表"最好"，3 不代表"最差"，跟名次、字母序都无关。用整数存类别是所有数据系统的通用做法（省空间、易比较）。想知道具体映射只能查平台映射表，考试不考。
- **实际写 Alpha 时看不到这些数字**：直接写 `sector` 即可，平台自己知道谁属于哪组。理解编码是为了明白下面这条禁忌。

**⚠️ 最重要的禁忌：它不能参与算术运算**

```python
group_rank(-ts_rank(close,5), sector)   # ✅ 正确用法：当 group_* 的分组依据
sector > 1                              # ❌ 无意义：1 并不"大于" 0
rank(close) * sector                    # ❌ 无意义：0 乘任何数都得 0，整组被抹掉
```

因为它回答的是"归哪一组"（类别标签），不是"值是多少"（连续数值）。拿它做比较或乘法，就是**把标签当数字用**——这是分组字段最典型的误用。

### 完整字段表截图

![股票价格成交量数据字段表](docs/images/dataset_pv_table.png)

### 典型 Alpha 思路

- 价格动量：`ts_rank(close, 20)`、`ts_av_diff(close, 20)`
- 反转：`group_rank(-ts_rank(close, 5), industry)`
- 量价关系：`ts_corr(close, volume, 20)`
- 流动性筛选：`volume > ADV20`

## 三、股票公司基本面数据（Fundamental）

### 业务含义

基本面分析涉及股票交易和价格历史以外的任何数据，这些数据可能影响股票价格或感知价值。它侧重于描绘公司画像，识别股票内在价值，并据此买入或卖出。

### 常用基本面指标

- 资产和股本回报率（ROA、ROE）
- 普通股和优先股股息
- 销售额、债务和收入
- 负债和资产
- 存货和销货成本
- 现金流（销售 CF、经营 CF、财务 CF 等）

### 数据频率

- 根据公司及上市交易所不同，报告要求和数据频率不同（季度、半年度、年度）。
- 公司可能错过定期更新，因此频率不一定规律。
- 表中未明确说明频率的字段，频率可能变化（如从季度到半年度）。

### 完整字段表截图

![股票公司基本面数据字段表](docs/images/dataset_fundamental_table.png)

### 典型 Alpha 思路

- 价值因子：`ebit/ev`、`cf/ev`、`liabilities/assets`
- 盈利能力：`roa`、`roe`、`operating_margin`
- 财务质量：`cashflow_op / net_income`
- 成长：`ts_av_diff(rev/assets, 30)`

## 四、股票分析师预估数据（Analyst Estimate）

### 业务含义

分析师预估数据包含金融分析师对公司各种财务指标的预测。通常包括：

- 每股收益（EPS）一致预期
- 收入（Revenue）一致预期

这些数字最常针对：季度、财年、下一财年给出，因此更新频率较低。

### 关键认知

- 分析师基于预测、模型、情绪和研究对公司未来表现作出估计。
- 估计不是精确科学，这解释了为什么当季度盈利/收入数字偏离一致预期时，股价会迅速根据新信息调整。
- **`est_*` 和 `etz_*` 数据可能来自不同的分析师群体**。

### 完整字段表截图

![股票分析师预估数据字段表](docs/images/dataset_analyst_table.png)

### 典型 Alpha 思路

- 预期修正：`etz_eps_delta`、`etz_revenue_delta`
- 预期惊喜：实际值 vs 一致预期
- 分析师情绪变化：`etz_eps_ret`（预期变化百分比）

## 五、股票情绪数据（Sentiment）

### 业务含义

情绪数据使用大量新闻和社交媒体帖子，估计市场参与者对股票价格方向的预期。信息来源包括新闻、tweets、文章、博客、留言板帖子等，并确定其对个股的集体观点。

大多数情绪数据都有关联得分，表示情绪的强度和/或方向。

### 完整字段表截图

![股票情绪数据字段表](docs/images/dataset_sentiment_table.png)

### 主要字段

| 字段 | 含义 |
|---|---|
| snt_bearish | 看跌情绪 |
| snt_bullish | 看涨情绪 |
| snt_buzz | 情绪热度；平均值为 1，<1 表示低强度，>1 表示高强度 |
| snt_buzz_bfl | 与 snt_buzz 相同，但缺失时回填平均值 1 |
| snt_ratio | 看涨情绪与看跌情绪的比率 |
| snt_value | 情绪倾向；<0 为负面，>0 为正面 |
| snt_volume | 社交媒体情绪量；数值越高表示活动越多 |

### 典型 Alpha 思路

- 情绪反转：`snt_bullish - snt_bearish`
- 情绪强度：`snt_buzz`
- 情绪变化率：`ts_av_diff(snt_ratio, 5)`

## 六、美国新闻数据（US News）

### 业务含义

新闻数据提供关于市场中潜在新闻驱动型波动的最新信息，有潜力帮助创建强劲、稳健且高收益的 Alpha。

### 关键使用建议

- 新闻本质上是 **delay 0** 数据，但平台**鼓励在 delay 1 上开发 Alpha**。
- delay 1 Alpha 不仅容量更大，而且考虑到新闻的噪声特性，通常更稳健。
- 可交易新闻的影响通常持续远长于几分钟或一天，有时甚至持续一个月、一个季度或更久。
- 大多数 US News 字段涉及新闻发布前后时间段内的价格或成交量及其变动，**而不是新闻发布的实际内容或情绪**。

### US 新闻数据能力

- 将金融新闻与市场数据匹配。
- 分析股票对突发新闻和预期公告实时发生时的反应。
- 75 个分析选项 + 同步的实时新闻和市场数据。
- 结合新闻和股票价格，提供全面洞察以增强交易决策。
- 在传统量化因子之外提供额外的 Alpha 来源。

### 完整字段表截图

![美国新闻数据字段表](docs/images/dataset_news_table.png)

### 典型 Alpha 思路

- 新闻事件冲击：`news_abs_return_5min`、`news_volume_5min`
- 隔夜/盘前反应：`news_pre_return`
- 新闻与价格背离：`news_return_1h - returns`

## 七、股票关系数据（Relationship）

### 业务含义

关系数据包含与某公司业务相关的其他上市公司的信息。例如，`customers` 指的是作为该公司客户的其他上市公司。

### 适用类别

- 客户（cust）
- 竞争对手（comp）
- 战略合作伙伴（part）
- 所有关系（all）

### 典型 Alpha 思路

- 供应链传导：客户公司的利好 → 供应商股价上涨
- 竞争映射：竞争对手下跌 → 本公司相对强势

## 八、考试速查卡

### 6 大数据集类别

| 类别 | 数据频率 | 核心用途 | 典型字段 |
|---|---|---|---|
| 价量（PV） | 日频 | 动量、反转、流动性、量价关系 | close, volume, vwap, returns, ADV20 |
| 基本面 | 季度/年度 | 价值、盈利、质量、成长 | ebit/ev, roa, liabilities/assets |
| 分析师预估 | 季度/年度 | 预期修正、惊喜 | est_eps, etz_eps_delta, etz_revenue |
| 情绪 | 日频 | 市场情绪、社交媒体热度 | snt_bullish, snt_buzz, snt_ratio |
| 新闻 | 日频/事件 | 事件驱动、新闻冲击 | news_return_5min, news_volume_1h |
| 关系 | 低频 | 供应链、竞争映射 | customers, competitors, partners |

### 价量数据关键规则

- ✅ 使用 `open/high/low/close/volume/vwap/sharesout`（已调整）
- ❌ 不要直接使用原始价格/成交量
- ⚠️ 股息、拆分数据仅在事件发生当天有值
- ⚠️ 与每日数据结合时注意 NaN

### 新闻数据关键规则

- 本质 delay 0，但建议 delay 1
- 字段多为价格/成交量变动，不是内容/情绪
- 影响可持续数周至数月

### 分析师数据关键规则

- `est_*` 和 `etz_*` 可能来自不同分析师群体
- 更新频率低，但偏离一致预期时股价反应快

## 九、易错点

1. **用原始价格做 Alpha**：必须等平台调整后的字段，否则拆股后价格断层会让 Alpha 不稳定。
2. **忽视 NaN**：股息、拆分、分析师更新都是事件型数据，与每日数据混用时要处理缺失值。
3. **把新闻字段当成情绪**：US News 字段多是价格/成交量在新闻前后的变化，不是文本情绪。
4. **混淆 est 和 etz**：`est_*` 和 `etz_*` 可能来自不同分析师群体，不要默认等价。
5. **只看高频数据**：基本面和分析师数据虽低频，但往往是稳健 Alpha 的重要来源。
6. **关系数据方向搞反**：客户强不一定供应商强，需验证传导方向。
