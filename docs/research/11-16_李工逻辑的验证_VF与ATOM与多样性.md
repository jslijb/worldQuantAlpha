### ③ "先有 idea → 再选数据集 → 最后算子只是变化手段"——**这是我方法上的根本错误，已被受控实验证实**

**我过去的顺序**：先扫"蓝海字段"（`fields_bluesea.json`，按 alphaCount 升序）→ 再套模板 → 再调参数。
**这是"字段驱动"，不是"idea 驱动"。**

**11-15 那 21 条的构造证据**：
- ATOMB 11 条 = **单字段 + 1~2 层算子**（生成脚本注释原文：「表达式只做单字段变换」）
- ATOM1115 11 条 = **多字段但各自独立归一化后任意符号相加**
  （`group_zscore(ts_decay_linear(ts_rank(A) ± ts_zscore(B) ± ts_mean(ts_zscore(C)),N),subindustry)`）
- 21 条里**只有 3 条含比值/乘法/条件** ⇒ **三个不相关信号直接融合，信号互抵 + 幅度失真**
  ⇒ **这就是你说的"有干扰"，你说对了。**

**受控实验（12 条，同字段同设置只改构造深度，已跑完）**：

| 数据集 | 浅构造 S | 深构造 S | ΔS |
|---|---|---|---|

| social12 | −0.32 | −0.11 | +0.21 |
| mmp | 0.42 | −0.09 | −0.51 |

**3 涨 3 跌、振幅 ±0.6 ⇒ "挖深"本身不产生 alpha。**
⇒ 决定 S 的是**形态要素是否齐全**，不是算子堆得多。

**形态对照实验（option9，5 条）**：

| 表达式 | S | 说明 |
|---|---|---|
| `group_rank(ts_av_diff(oi_10,20) - ts_av_diff(oi_360,60), subindustry)` | **0.86** | **跨期限差分（期限结构变化）** |
| `group_scale(ts_av_diff(oi_10,20)/ts_std_dev(oi_10,60), subindustry)` | 0.50 | 比值 + group_scale |
| `group_rank(ts_zscore(ts_av_diff(oi_10,20)/ts_std_dev(oi_10,60),250), subindustry)` | 0.43 | 多一层时序归一化 |
| `group_rank(ts_av_diff(oi_10,20)/ts_std_dev(oi_10,60), subindustry)` | 0.42 | 比值 + group_rank |
| `group_zscore(ts_av_diff(oi_10,20)/ts_std_dev(oi_10,60), subindustry)` | 0.32 | 比值 + group_zscore |
| `group_rank(pcr_oi_10/pcr_oi_360, subindustry)` | **−0.09** | **只有比值、无差分** |

**分组算子对照**：group_rank 0.42 / group_scale 0.50 / group_zscore 0.32；
分组字段 industry 0.48 / subindustry 0.42 / sector 0.41。

⇒ **三条实证结论**：
1. **必须有"差分"（时序变化）**——X3 只有比值 = −0.09；这正是"idea 决定形态"的体现：
   期限结构的变化有意义，水平比值没意义。
2. **时序归一化不是压制源**（X1 0.42 vs X4 0.43）——我"先归一化毁关系"的假设**不成立**。
3. **算子只是形态的调节旋钮**——同一 idea 下，换分组算子 S 在 0.32~0.50 摆动，
   换 idea（期限差 vs 比值）S 从 0.42 跳到 0.86。**这正好支持你说的"先有 idea，算子只是加减乘除"**。

### ④ "多样性是批次层面的数据集均衡，不是单条表达式里混数据集"——**你说得对，我之前理解偏了**

**我的错误表述**：在 `MEMORY.md` / `AGENTS.md` 里写「数据集分散多样化——每日新数据集/新字段开荒」时，
虽然字面没错，但在**回答层**我把它和"一条 alpha 用多个数据集"混着讲，造成了"ATOM 与多样性冲突"的错觉。

**事实**：
- ATOM = 一条 alpha 只用一个数据集（**禁**混）
- 多样性 = 一批 alpha 里各数据集使用次数均衡（**要**均衡）
- **两者完全不冲突**，且论坛 VF 复盘证明它们是**同向的**：
  「atom 比例高 → VF 高」「真实 P3（atom 支撑）高 → VF 高」

**我们现状**：360 条里 atom 2.8%、数据集组合 Top1（f23+f6+pv1）占 27.2%、
Top8 字段占引用 50.1% ⇒ **批次层面严重不均衡**。

### ⑤ "证明用量价的数据算 ATOM"——**已证明，但要区分两个层次**

**平台标签层（成立）**：11-15 四条的 `GET /alphas/{id}` 返回
`classifications: ['DATA_USAGE:SINGLE_DATA_SET', 'REGULAR:REGULAR']` ⇒ **平台判它是 ATOM**。

**但 VF 层（你的质疑成立）**：量价单数据集 alpha **占满了最拥挤的格子**。
- 台账 360 条里 `returns`/`close`/`volume`/`cap` 合计引用 807 次（占 3181 次的 25.4%）
- 存量池 445 条全死，平台 corr 最低 0.7754，**全是同族早被收录**
- 论坛：「SC 0.7 是平台让你交的线，**不是 VF 愿意给你分的线**」；按 SC 分桶，
  **SC 0.6~0.7 组的 atom 比例只剩 43%** ⇒ **越是被平台收下的量产 alpha，越拉低 VF**

⇒ **量价 + ATOM = 平台会收，但 VF 会降。** 这是"合规但无边际信息"。
主帖说得更直接：单字段 ATOM 的价值在于「**扫描新字段**」——
`alphaCount==0` 的新数据集字段才配叫"干净的边际信息"。

## 三、必须补的第四道门（平台目标对齐）

| 门 | 判据 | 平台依据 |
|---|---|---|
| **门 7：单 alpha 字段数上限** | 每条 alpha 使用的不同字段数 ≤ **2**（单字段 ATOM = 1） | Genius Tie-Breaker「Avg distinct Fields 越低越好」 |
| **门 8：季度不同字段总数下限** | 每批至少引入 N 个**台账从未用过**的字段（N≥2 已定） | Genius Tie-Breaker「Total distinct Fields 越高越好」+ 主帖「扫描新字段」 |
| **门 9：atom 比例下限** | 一批新提交里 atom 条数占比 ≥ **50%**（论坛低 VF 线的下限） | VF 复盘帖：atom 50.5% ⇒ VF 0.39，81.7% ⇒ VF 0.97 |

⚠ **门 7 与我刚建的"深度门"存在张力**：深度门要求"关系 + 多层变换"，
而平台要"字段数 ≤2"。**两者可以同时满足**——关系可以用**同一字段的多个变换**做
（如 `ts_av_diff(x,20)/ts_std_dev(x,60)`），不必引入第二个字段。
**这恰恰是"单字段深挖"的正确形态**，也是主帖给的 4 条单字段模板的共同特征。
⇒ **下一步的正确方向不是"更多字段"，是"单字段 + 反复变换 + 横截面排序"。**
