## 一、设置总览

| 设置项 | 作用 | 考试重点 |
|---|---|---|
| Language | 表达式语言 | 目前只用 **Fast Expression** |
| Instrument type | 金融工具类型 | 目前仅支持 **Equity（股票）** |
| Region / Universe | 地域与股票池 | 普通用户只能用 **USA**；Europe / Asia 仅对顾问开放 |
| Delay | 数据延迟 | `0` = 用今天数据今天交易；`1` = 用今天数据明天交易 |
| Decay | 衰减 | 整数 `n ≥ 0`，降换手但会削弱信号 |
| Truncation | 权重截断 | `0 ≤ x ≤ 1`，建议 `0.05–0.1`（单只最大 5–10%） |
| Neutralization | 中性化 | Market / Industry / Subindustry，使 Alpha 在分组内均值为 0 |
| Lookback Days | 回望天数 | 影响部分时间序列/分组算子的历史窗口长度（如 252、66） |
| Pasteurization | 池外标的置空（按池过滤） | 默认 **On**：非 Universe 标的置为 NaN |
| NaN Handling | NaN 处理 | 默认 **Off**：保留 NaN，需手动处理 |
| Unit Handling | 单位校验 | 检测不兼容单位（如 price + volume）并警告 |
| Max Trade / Max Position | 交易/持仓限制 | 默认 **Off**，可配置单日最大交易金额或持仓限制 |
| Test Period | 测试周期 | 从 IS 划出 Train/Test，默认 0 年；防过拟合；显示后才能提交 |

## 二、逐项详解

### 2.1 Language

BRAIN 使用 **Fast Expression** 作为表达式语言。表达式由 **数据字段、算子、数值** 组成，支持多行注释 `/**/`、以 `;` 分隔语句（最后一行不加 `;`）。

### 2.2 Instrument type

目前仅支持 **Equity（股票）**。

### 2.3 Region and Universe

- **Region**：目前普通用户唯一可用区域是 **USA**。Europe 和 Asia 仅对研究顾问开放。
- **Universe（股票池）**：BRAIN 预先准备的可交易金融工具集合。
  - 例：`US: TOP3000` 表示美国市场流动性最高的前 3000 只股票（按平均每日美元成交额排序）。

### 2.4 Delay（延迟）

Delay 表示**决策时数据的可获得性**。

- **Delay 0**：今天收盘前看到数据，**今天收盘前**就交易。仓位基于当天可获取的数据建立。
- **Delay 1**：今天看到数据，**明天**才交易。仓位存在 1 天滞后，基于今天的数据。

> 在 Fast Expression 中，delay 已由设置自动处理，无需在表达式里手动写 `ts_delay`。

### 2.5 Decay（衰减）

对过去 `n` 天执行线性衰减，把今天的值与之前日期的衰减值结合起来。

![Decay 线性衰减公式](docs/images/decay_formula.png)

- **合法值**：整数 `n`，且 `n ≥ 0`。
- **注意**：用负值或非整数值会导致回测失败。
- **作用**：可降低换手率；但 `decay` 太大会削弱信号强度。

### 2.6 Truncation（截断）

限制投资组合中每只股票的最大权重。

- **合法值**：浮点数 `x`，且 `0 ≤ x ≤ 1`。
- **0** 表示不限制。
- **建议值**：`0.05` 到 `0.1`（即单只股票最大权重 5%–10%）。
- **目的**：避免对单只股票波动过度暴露，降低回撤风险。

### 2.7 Neutralization（中性化）

使策略对市场 / 行业 / 子行业保持中性。

- **Market 中性化**：
  ```
  Alpha = Alpha – mean(Alpha)
  ```
  使 Alpha 向量均值为 0，多头敞口完全抵消空头敞口，净仓位为 0。
- **Industry / Subindustry 中性化**：把股票按行业/子行业分组，再在每个分组内分别做均值中性化。

> 行业/子行业分类可参考 **GICS**，但不一定是 BRAIN 平台使用的同一标准。更多细节请参阅 BRAIN 官方文档中的 **Neutralization FAQ** 部分。

### 2.7.1 Lookback Days（回望天数）

设置面板中有一个独立的 **Lookback Days** 字段（常见值如 `252`、`66`）。它影响部分算子默认的历史窗口长度，尤其在用基本面/季度数据时经常配合 `66`（约一季度）或 `252`（约一年）使用。

### 2.8 Pasteurization（池外标的置空 / 按池过滤）

> **译法说明**：官方借用"巴氏消毒法（pasteurization）"作比喻，实际含义是**净化数据范围**——把**不在所选股票池（Universe）内**的标的输入值替换为 NaN，使其不参与后续计算。注意：它**不是"给股票消毒"**，也**不是处理异常值/去极值**（去极值是 `winsorize` 的职责；限制单票权重是 `truncation` 的职责）。中文按量化语境应理解为**按股票池过滤（池外置空）**。

把不在 Alpha 股票池中的金融工具的输入值替换为 **NaN**。

![Pasteurize 设置](docs/images/pasteurize_setting.png)

- **Pasteurize = On（默认）**：不在所选 Universe 中的标的数据转为 NaN。
  - 优点：仅 Universe 内标的有非 NaN 值，更适合横截面/分组操作。
- **Pasteurize = Off**：不执行自动替换，所有可用输入都使用；可用 `pasteurize(x)` 算子手动控制。

**示例**：

```
group_rank(pasteurize(sales_growth), sector) - group_rank(sales_growth, sector)
```

| 设置 | 值 |
|---|---|
| Region | USA |
| Universe | TOP3000 |
| Delay | 1 |
| Decay | 4 |
| Truncation | 0.01 |
| Neutralization | Market |
| Pasteurization | On |

- 第一个 `group_rank` 用 `pasteurize` 把输入限制到 **Alpha 股票池（TOP500）**；
- 第二个 `group_rank` 在 **所有金融工具** 中对 `sales_growth` 做行业排名；
- 两者相减，衡量同一行业内 Alpha 池内外的排名差异。

### 2.9 NaN Handling

控制 NaN 如何被处理。

![NaN Handling 设置](docs/images/nan_handling_setting.png)

- **NaNHandling = On**：
  - 时间序列算子：如果所有输入都是 NaN，返回 **0**。
  - 分组算子：若某标的输入为 NaN，返回该分组对应的统计值。
  - 副作用：会提高覆盖率，但可能引入有歧义的信息。
- **NaNHandling = Off（默认）**：
  - 时间序列算子：若所有输入都是 NaN，返回 **NaN**。
  - 分组算子：若某标的输入为 NaN，返回 **NaN**。
  - 需要手动处理 NaN。

**示例 1**：

```
ts_zscore(etz_eps, 252)
```

- 当 `NaNHandling = On` 时，若某股票 252 天内 `etz_eps` 全为 NaN，返回 0。
- 但 `x == ts_mean(x, d)` 时 `ts_zscore(x, d)` 也会返回 0，因此无法区分"无数据"和"数据等于均值"。
- 若 `NaNHandling = Off`，可手动处理：

```
is_nan(ts_zscore(etz_eps, 252)) ? ts_zscore(est_eps, 252) : ts_zscore(etz_eps, 252)
```

**示例 2**：

```
groupmax(sales, industry)
```

- `NaNHandling = Off` 且某标的 `sales` 为 NaN → 输出 NaN。
- `NaNHandling = On` 且某标的 `sales` 为 NaN → 输出该行业 `sales` 最大值。

### 2.10 Unit Handling

当表达式中使用了单位不兼容的数据字段时发出警告。

- 例如：把 `price` 与 `volume` 相加，单位不一致，会触发警告。
- 设置项可配置为 `Verify` 等模式。

### 2.11 Max Trade / Max Position（交易与持仓限制）

设置面板底部还有 **Max Trade** 和 **Max Position** 选项。

- **Max Trade**：限制单日最大交易金额/比例。
- **Max Position**：限制组合中某只标的的最大持仓金额/比例。
- 默认情况下通常设置为 **Off**。开启后可用于控制极端权重和流动性风险。

> 在面板截图中，Max Trade 和 Max Position 均显示为 **OFF**。

### 2.12 Test Period（测试周期）

测试周期是一项**帮助规避过拟合**的功能，允许您从 IS 周期中单独划出一段作为测试周期（Test），为验证研究思路提供更灵活的方法。

**核心目的**：将样本内（IS）周期划分为**训练周期（Train）**和**测试周期（Test）**。
- 训练周期用于**开发** Alpha 和 SuperAlpha；
- 测试周期用于**验证** Alpha 和 SuperAlpha；
- 基于训练周期回测结果开发、且在两个周期**都表现良好**的 Alpha，很可能是适合提交的强力候选，并可能避免过拟合。

**如何使用**：
- 在回测设置中，可定义与 IS 周期**最后 0–5 年**对应的测试周期。
- **默认不设置测试周期（0 年）**。

**对回测的影响**：
- 选择测试周期**不直接影响回测数值**，但会影响统计数据和可视化。
- **提交测试**在整个 5 年周期上运行；**回测**在整个 5 年 IS 上运行。
- 若选择了测试周期，回测统计会被**分为两部分**：训练周期部分 + 测试周期部分。

**可视化与识别**：
- 统计摘要默认以**训练周期**为准。
- 点击 **"显示测试周期"** 按钮可查看测试周期的统计数据。
- 图表上代表测试周期的线条以**橙色**显示；训练周期为蓝色。
- 在"摘要"区域可选择 **TEST** 或 **IS**，分别查看测试周期或整个 IS 周期的统计摘要。
- 用 **"隐藏测试周期"** 按钮可隐藏测试周期。

> ⚠️ **重要约束**：只有通过单击"显示测试周期"按钮**显示测试周期后**，Alpha 或 SuperAlpha 才能提交。

**年度统计划分**：年度 IS 统计数据在训练周期和测试周期之间划分，分别以**蓝色（Train）**和**橙色（Test）**指示符表示。

## 五、常见坑点

1. **Decay 用负值或非整数**：直接回测失败，必须是非负整数。
2. **Truncation 超出 `[0,1]`**：可能破坏回测。
3. **Delay 和 `ts_delay` 混淆**：Delay 是设置层自动偏移；`ts_delay(x, d)` 是表达式层手动取历史值。
4. **Pasteurize=On 时做全市场 rank**：不在 Universe 里的标的是 NaN，全市场排名会只覆盖 Universe。
5. **NaNHandling=On 引入 0 和真实均值 0 难区分**：覆盖率高但信息可能失真。
6. **Region 选错**：普通用户若选 Europe/Asia 可能无法回测或结果为空。
