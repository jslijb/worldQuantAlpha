- **★ 墙是自己砌的（0915 实证）**：瓶颈不是外部竞争，是**候选池自身同质**。w11x 池 99 条里 **95% 共享** `ts_av_diff(cash/assets,45)` + `ts_av_diff(cashflow_op/enterprise_value,45)`，88% 再加 `-ts_delta(close,2)`；已提交池字段频次 assets 97% / close 97% / volume 83% / cash 73%，中性化 SUBINDUSTRY 93% → corr 天然 0.74~0.93。
- **豁免路径并非全死（0915 修正）**：豁免线 = 1.10×max(**该候选自己** corr≥0.7 的对手的 S)，**不是**全池最高 S。实测 w122_a `akLp3pzW` corr=**0.8036**（≥0.7），S=2.78 ≥ 1.10×≈2.53 → **靠豁免入池**（ACTIVE/OS）。所以"豁免线恒在 3.79"只在遇到 `0mR2K6lr`(S=3.45) 当热对手时成立；**热对手随候选而变**，别把它当全局常数。**直通仍是主线（corr<0.70），但豁免不是死路。**
- **可开采空间**：`fnd6_matrix.json` 574 个 MATRIX 字段中 **522 个从未被用过**（最冷 `fnd6_newqv1300_spcep12` aC=9）。换**没用过的锚**是首选破墙动作。

### Research Paper 16：分析师短期交易思路（0915）
- Birru / Gokkaya / Liu / Stulz, *Journal of Finance* 77(3):1829-1875 (2022)，DOI 10.1111/jofi.13130。
- 论文自家三版 S+F 仅 1.86 / 2.08 / 2.69，**远低于 4.0 门槛——不能照搬，只能移植结构**。论文讲 trade ideas，表达式实现的是评级变化，**不是同一数据对象**。
- **两条铁律**：① `ts_mean` 对**离散字段**降换手无效，须先连续化（rank/zscore/vec_avg）再平滑；② **`? : NaN` 是权重集中（CONCENTRATED_WEIGHT）头号成因**，改 `if_else(cond,·,0)`。降换手：`trade_when` 第三参用 **-1**（保持仓位）而非 0；`hump(x,0.01)` 优于 ts_mean。
- **字段权限**：账号**无独立 analyst 数据集**，**`rating` 字段 404**。等价 4 个评级字段全在 analyst4 且**全为 VECTOR，必须 `vec_avg`**：`anl4_fs_detail_rec_v4_nd_estimate`(aC=24，最冷门) / `anl4_basicdetailrec_ratingvalue`(574) / `anl4_eaz2lrec_ratingvalue`(5886，热) / `anl4_total_rec`(2646)。delay=0/1 均可用。
- **修正 0914**：**市值分桶中性化不是普适杠杆**，只在信号已有质量基础时放大效果。
- **改写 0913 的"analyst4 撞墙"**：撞墙的是**离散度/估值轴**；**评级偏离度轴可用**。瓶颈不在质量在相关性——没跑 corr 不下结论。
- **风险**：同骨架共用分位桶会互撞（0913 实证 0.82–0.95）→ 提交前须备多个不同桶 + 不同锚变体。

## corr 服务与探测（0915 二次修订）
- `200 + Retry-After + 空 body` = **平台正在现算，不是故障** —— 这个方向对。但**"3–4 次轮询即返回"在当前不成立**：0915 17:30 实测 51 次/90 秒、180 秒预算、一次性快扫三种方式**都拿不到 records**，且**全程零 429** → 准确表述是**相关计算在账号侧排队积压**（非故障、非封禁）。
- **★ 能确凿拿到 corr 数值的唯一入口**：alpha **提交成功（ACTIVE）之后**读 `GET /alphas/{id}` 的 `is.selfCorrelation`（实证 w122_a `akLp3pzW`=0.8036）。未提交状态下无其他取数入口。
- **⚠️ 反向修正（自己差点写错，已对照验证）**：`is.checks` 里的 `SELF_CORRELATION=PENDING` **不是"正在计算"的信号**，而是**所有未提交 alpha 的默认占位符**（对照 5 条从未触碰的候选 `O0r3epMg`/`le8mxdn7`/`3q9NMgk6`/`6XrkW6R5`/`KPOAOXEE`，全部 checks=8 条、全部 PENDING）。别拿它判断提交是否触发。
- **⛔ 不要再靠 `correlations/self` 反复打**：一条候选上百次请求，**探测本身就是积压的成因**（0915 本轮探针+预检约 380 次请求）。
- **⚠️ 反向修正**：此前"提交链路一直可用、47+ 条白积压"的结论**站不住**——`corr_only.py` 对 2 条实测双 TIMEOUT、`corr_ready_0915.txt` 快扫为空，说明当时确实取不到数。"探针判据写错"是原因之一，但不是全部。
- **⛔ 缓存探针 `E5vj5YdL` 无效**（实测 = UNSUBMITTED，不在已提交池 → 永远返回空，"假阴性"来源）。正确缓存探针 = 已提交的 **`E5vx6NJP`**（ACTIVE, selfCorr 0.6598）。
- **盲提交 `src/submit/blind_submit.py`**：绕过预检直接 `POST /submit`。实证一成一败——`akLp3pzW` 成功入池；`883wqwVX` POST 200/201 后**提交状态轮询 59 轮（~8 分钟）全为空、未裁决**（复现 0914 互堵模式）。**纪律：一次只提一个，出现 PENDING 立即停手**，否则堵死管道。

## 关键事实
- selfCorr ≥ 0.7 触发 Production Correlation 测试；通过 = max corr < 0.7 **或** Sharpe 比相关 alpha 高 10%。
- Sharpe ≈ 15.8 × IR（BRAIN 的 Sharpe 即 IR 年化版）。
- Fitness = Sharpe × √(|R| / max(T, 0.125))。
