## 一、问题定义：旧骨架依赖是实的，且机器门没拦住

### 1.1 三个量化事实

| 指标 | 实测值 | 出处 |
|---|---|---|
| 台账不同算子骨架签名 | **256 个** / 360 条；Top12 骨架合计约 71 条 ≈ **19.7%** | 本地按 `ops+分组字段` 归一化统计 |
| 字段引用集中度 | 引用总次 3181，**Top8 字段占 50.1%** | `src.core.atom.fields_of()` 逐条解析 |
| 字段池覆盖率 | 用了 **258 / 4375 = 5.9%** | 同上 + `all_fields_*.json` |
| 数据集组合 Top1 | fundamental23+fundamental6+pv1 = **98 条 = 27.2%** | `judge()` 逐条判定 |

### 1.2 但"旧骨架"不是唯一病根 —— 平台标签已经放过它了

**平台对 11-15 四条常规的官方分类（`GET /alphas/{id}` 真值）**：

```
d5al5ljw / LLKlxA7m / YPaWd16q / WjlWKLPj
  region=GLB  universe=MINVOL1M  neutralization=STATISTICAL  decay=64
  classifications = ['DATA_USAGE:SINGLE_DATA_SET', 'REGULAR:REGULAR']
```

⇒ **平台口径下它们就是 ATOM**。但四条的数据集全是 pv1、字段全是 `returns`、
算子全是 `group_scale` 双腿，只换分组参数（industry/sector/exchange/sector+country）。

> ★ **ATOM 合规 ≠ 有多样性。** ATOM 是"不许混数据集"的**禁**，多样性是"要换数据集/字段/机制"的**要**。
> 把 ATOM 当多样性的证明，就会出现"形式 100% 合规、实质 4 个参数变体"的批次。

**GLB 量价这条路在字段层面已经走到头**（不是"再换几个分组参数"能救的）：

- GLB 的 pv1 字段池**只有 9 个**：`adjfactor / adv20 / cap / close / country / currency / cusip / dividend / exchange`
- 台账已用：`close` 245 次、`cap` 95 次、`adv20` 5 次
- **未用过的 pv1 字段：4 个**
- 附带修正：**GLB 的 pv1 里没有 `returns`**（`returns` 属 USA 侧 pv1），GLB 量价实际用 `close`

## 二、为什么现有门形同虚设（代码走查）

### 2.1 `diversity.py` 的 `idea` 维度是"改名就绕过"

```python
# _grid/diversity.py:158-162  parse_alpha()
idea = a.get('idea_id') or a.get('idea') or a.get('kernel')
if not idea:
    _cid = str(a.get('cid') or a.get('aid') or '')
    idea = _cid.split('_')[0] if _cid else '?'
```

- 台账 360 条的 `batch` 前缀共 **212 种**（Top1 `0916-v3-auto` 53 条）⇒ 这个维度几乎永远不超限。
- 唯一有意义的用法是 11-15 那批显式 `idea_id`（`I01_CFO收益率变化` … `I10_量价长期分位`，共 10 条），
  但**只有 11-15 那一批用了**。
- ⇒ **换批次名就能过门**。这就是"复制旧代码不校验直接开始"的机械原因。

### 2.2 `DIMS` 缺 field 与骨架两维

```python
# _grid/diversity.py:47
DIMS = ('dataset', 'idea', 'operator', 'universe', 'neutralization', 'decay', 'truncation')
```

字段维缺失 ⇒ 换字段不受限；骨架维缺失 ⇒ 换外壳换窗口不受限。
`operator` 维只统计**算子出现次数**，不统计**算子组合结构** ⇒ 同一算子序列反复用照样过。

### 2.3 机制去重的真判据已被找到，但没接进提交通道

- `mech_gate.py` 的字段 Jaccard 判据 **11-15 已被 PnL 实测推翻**（`replay_corr.py`，341 条真实 PnL）：
  字段同源 20 条两两 corr 中位 0.2718 / 组合 Sharpe 4.176；字段跨源 20 条中位 0.3309 / 3.747
  ⇒ 字段集合不是 PnL 相关的代理，该门只能当粗筛。
- **`corr_gate.py` 才是有效判据**（`rho* = b/a` 充要条件，400 对真实 PnL 预测 ΔS 符号一致率 100%）。
- 但 `now_submit.py` 头部自述：**"为什么不走本地 corr_gate 先行：corr_gate 留作事后解释用。"**
  ⇒ 提交前只查平台 prod/self（≤0.69），**没有一道本地门问"这条是不是旧件"**。

### 2.4 结论：问题不是"规则写错了"，是"规则没有落成不可绕过的代码"

现有 4 道门各自的缺口：

| 门 | 位置 | 缺口 |
|---|---|---|
| ATOM 判定 | `src/core/atom.py` | 字段映射跨市场串味（USA=fundamental6 / EUR=fundamental23），标签可能错 |
| 算子禁用 | `_grid/op_ban.py` | 只禁**算子名**，不管**骨架结构** |
| 多样性 | `_grid/diversity.py` | idea 用 cid 前缀、DIMS 缺 field/骨架 |
| 机制去重 | `_grid/corr_gate.py` | **有效但未接入提交通道** |

## 三、方案：五道代码级硬门（全部机器强制，人绕不过）

> 纪律：**每道门都必须在"发模拟之前"拦截**，不能事后解释。
> 接入点统一在 `_autologs/sim_run.py`（当前唯一发模拟的通道，已接 diversity）与 `_grid/now_submit.py`（提交通道）。

### 门 1｜`idea` 改显式登记，缺失即拒
- **改**：`diversity.py:parse_alpha()` —— 删掉 `cid.split('_')[0]` 兜底，改为
  `idea = a.get('idea_id')`；取不到直接返回 `{'idea': {'?': 1}}` 并由 gate 判违规。
- **配套**：`batch_gen.py.build_batch()` 增加 `idea_id` 必填参数（**没有 idea_id 的核不许进批**）。
- **判据**：批次里 `idea='?'` 的条数 > 0 ⇒ 整批拒绝产出。
- **依据**：MEMORY.md §〇4-4 + §五"每条候选必须能用一句话说清在赌什么"。

### 门 2｜`DIMS` 加 `field` 与 `skeleton` 两维
- **改**：`diversity.py:DIMS` 加 `'field'`、`'skeleton'`。
- **field 维**：表达式里的**业务字段**（剔除 6 个豁免分组字段）逐个计数。
- **skeleton 维**：算子序列归一化后的签名（`ts_std_dev+ts_av_diff+group_scale` 之类，与分组参数无关）。
  ⚠ **分组参数必须剔除**，否则"只换 industry/sector"会被当成新骨架 —— 这正是 11-15 四条的形态。
- **判据**：同一 field 在库内占比 ≤ max(10%, 1/N)；同一 skeleton 同理。
  以台账实测反推：258 个已用字段下，单字段上限约 10% ⇒ `close` 245 次必然超限 ⇒ **该门会直接判死 close 家族**。
- **依据**：MEMORY.md §七 Top8 占 50.1% / 字段池 5.9%。

### 门 3｜骨架签名精确去重（对台账 256 个已用签名）
- **新文件**：`_grid/skel_guard.py`
- **做什么**：把候选表达式的 skeleton 签名与台账已提交的 256 个签名比对，
  **完全相同即拒**（不是份额限制，是"这条路已经吃过了"）。
- **依据**：11-15 四条的骨架签名 = `group_scale+ts_std_dev+ts_av_diff`（分组参数已剔除后四者同族）
  ⇒ 门 3 会把第 2 条起全部拦下，与"该家族每日 ≤1 条"的人工结论一致，且由机器执行。
- **配套**：`skeleton` 维再进一步允许"换算子结构"（如 `ts_std_dev` → `ts_quantile`）通过，
  逼出真正的结构多样性。

### 门 4｜`corr_gate` 前置到提交通道
- **改**：`now_submit.py` —— 在 POST 之前跑 `_grid/corr_gate.py` 判重，
  `maxCorr` 超阈值的候选**不进提交队列**（不是事后写报告）。
- **判据**：复用 corr_gate 现成的 `rho* = b/a` 门槛（400 对 PnL 符号一致率 100%）。
- **依据**：MEMORY.md §六。

### 门 5｜每批"新字段"下限
- **改**：`batch_gen.py.assert_diverse()`（或新增 `assert_new_fields()`）
- **判据**：每批至少 N 个字段是**台账未用过**的（N 待定，建议 ≥2）；且单批内同一 field 占比 ≤10%。
- **依据**：MEMORY.md §十 B5（258/4375 = 5.9%）。

### 附加门 6｜机制一句话必填（阻断"字段堆砌"）
- **改**：`batch_gen.py` 每个核必须带 `mech`（一句话说清在赌什么），空则拒绝产出。
- **依据**：11-15 那 12 条新数据集批全灭（S −0.40~0.67），根因就是三个不相关字段等权相加
  = 字段堆砌 ⇒ **机制说明是唯一能在模拟前识别噪声的手段**。
