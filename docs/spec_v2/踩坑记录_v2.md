# Alpha Loop v2 踩坑记录

> 原则：凡"实测推翻预期"的当场入档，同类坑禁止二犯。每条含现象/根因/正确做法/复验法。

## K-01 重复认证触发平台验证码（阻断级）

- **现象**：同一账号短时间内第二次 `POST /authentication` 返回
  `400 {"captcha":["This field is required."]}`，之后所有请求 401。
- **根因**：平台对频繁认证启用 captcha 挑战，脚本无法应答。
- **正确做法**：`auth.Brain` 持久化 cookie 到 `state/session.json`；登录前先
  `GET /users/self/alphas?limit=1` 探活，200 直接复用，不再认证。
- **复验**：连续两次 `python -m alpha_loop.auth`，第二次应打印 `LOGIN_OK` 且无 captcha。

## K-02 `/data-fields` 缺参数只返回 Invalid query

- **现象**：只传 `region`/`universe` 返回 400 `{"Invalid query"}`。
- **根因**：该接口要求 `instrumentType` 与 `delay`。
- **正确做法**：参数必须含
  `instrumentType=EQUITY&region=X&delay=1&universe=Y&limit=50&offset=N`。
- **复验**：`fielddb.FieldDB().load(region, universe, brain)` 返回 >0。

## K-03 `/users/self/alphas` 分页有硬上限

- **现象**：`limit` 传 500/1000 也只回 100；`offset` 超过 1000 报错。
- **根因**：平台分页硬限制。
- **正确做法**：`limit=100`，`offset` 递增；总量看响应 `count`，不要看翻页深度。
- **复验**：`baseline.fetch_alphas` 打印 `alphas_seen`。

## K-04 字段语义匹配"零命中"仍配出高分（最危险）

- **现象**：`fnd_cashflow_yield` 被配成 `accrued_acquisition_costs` +
  `deferred_charge_goodwill`；`opt_iv_rv_premium` 被配成 EPS skewness。
- **根因**：评分函数只要求 `coverage` 达标，关键词 `hits=0` 时仍拿覆盖率分数。
- **正确做法**：`hits == 0` 直接返回 `-1`（拒绝），宁可不生成候选；字段 `id`
  也纳入匹配文本（字段名常带语义）。
- **复验**：构造"现金流/企业价值"角色，返回字段必须含 cashflow/enterprise 语义。

## K-05 多样性 V4 在 2 条批次下必然触发

- **现象**：任意 2 条批次，同 idea 占比 50% > 阈值 30%，全部被拒。
- **根因**：占比判据没有考虑小样本。
- **正确做法**：V4 仅在 `len(batch) >= 4` 时生效。
- **复验**：`pytest alpha_loop/tests/test_gates_composer.py -k diversity`。

## K-06 全量拉字段 200 页太慢，阻断上线

- **现象**：GLB 10000 字段按 `limit=50` 需 200 次请求，实际数分钟未完成。
- **正确做法（临时）**：用分市场历史缓存（平台镜像）转成带 `region` 键的新格式救急，
  同时保留 `source=migrated_cache` 标记；后续用平台 API 刷新。
- **正确做法（长期）**：增量拉取 + 按数据集拉取（`dataset.id` 过滤），不整表扫。
- **复验**：`state/fielddb/GLB.json` 含 `region` 键且字段数 >5000。

## K-07 `group_neutralize` 未计入变换层导致误杀

- **现象**：形态 H 被判 `D2_layers=1`，深度门拒绝。
- **根因**：`NORM_OPS` 漏了 `group_neutralize`。
- **正确做法**：横截面运算符白名单与变换层判定表保持同一来源（`config.XOP_WHITELIST` 同步）。
- **复验**：`pytest ... -k depth_all_shapes` 9 形态全 PASS。

## K-08 baseline 与字段加载顺序错位

- **现象**：启动即解析历史 alpha，但字段表尚未加载，`dataset_of` 全空 → "已用数据集"为空。
- **根因**：`fetch_baseline` 在 `fdb.load` 之前调用，且一次解析所有市场。
- **正确做法**：先缓存原始 alpha 列表（`alphas_raw.json`），再按市场 `load` 后
  `parse_region` 增量解析。
- **复验**：`BASE GLB used_ds=` 打印值 >0。
