# 相关性墙破法（实战记录）

> 来源：项目 0910–0915 的实测记录 + 平台规则
> 这是本项目唯一真正的瓶颈——**质量关（S+F≥4.0）能挖出 460 条，但相关性关卡住 90%**

---

## 一、规则本身

| 项 | 内容 |
|---|---|
| 触发条件 | `selfCorrelation ≥ 0.7` 触发 Production Correlation 测试 |
| 通过条件 | **max corr < 0.7** **或** Sharpe 比相关 alpha 高 **10%** |
| 豁免线 | `1.10 × max(所有 corr≥0.7 对手的 Sharpe)`，候选 S 达线即可提交 |
| 计算对象 | **当前已提交池**（实时计算，非历史快照） |

---

## 二、最关键的一条性质：相关性是动态的

**实测**：同一个表达式，预检 corr 从 **0.616 → 0.9879**，只因中途提交了两个结构相似的因子。

**机理**：self-corr 是对"当前已提交池"实时算的 → 每提交一个因子，结构相似的兄弟因子 corr 立刻被顶高。

**三条推论**：
1. 提交后必须对剩余池**重新预检**，旧结论全部作废
2. 同构候选**严禁扎堆**提交
3. 必须常备多套**结构不同**的 PNL 储备

| 手法 | 实例 | corr | 关键动作 |

| **腿系数加权改 PNL 构成** | w85_a | **0.754 → 0.6803** | 独有 fnd2 锚**全权** + 共享 PV 尾部**降权 0.5**（0.3 质量崩，0.5 是甜点） |

### 共性
> **必须含"独有成分腿"** —— 即结构上别人复制不了的腿。

### 双轮换法则
> **锚腿（冷门字段）+ 价量腿同时换。**
> 只换一个没用（单锚嫁接稀释不够，batch74 corr 0.78–0.89）。
> 避开最拥挤的 `ts_delta(close,2)` + `volume/ts_mean(volume,60)`。

## 七、提交流程（含并发注意）

1. 质量闸门：S+F ≥ 4.0 且 testS ≥ 1.25 且 checks 无 FAIL
2. corr 预检：`GET /alphas/{id}/correlations/self`
3. 判定：max corr < 0.7 → 直通；否则算豁免线 = 1.10 × max(所有 corr≥0.7 对手的 S)，候选 S 达线也可提交
4. `POST /alphas/{id}/submit` → `GET /alphas/{id}` 核 `status == ACTIVE` → 追加台账

**并发警告**：同账号并发提交会互堵（0914 实测 w95_a/w96_a/w96_b/w101_e 四个 POST 201 后永不裁决，w101_f 秒过）→ **必须串行提交**。

## 八、拿到"相关判决"的正确入口（0915 实测，修正第 2 步）

### 8.1 事实

第 2 步用 corr 端点取数的做法，目前在本人账号上取不到数：

| 观测 | 结果 |
|---|---|
| 缓存探针 `E5vj5YdL` 连续轮询 **51 次 / 90 秒** | `200 + Retry-After:1.0 + bodylen=0`，始终无 records |
| 全新探针 `KPOAOXEE`（w112_a）同上 | 同样 90 秒无 records |
| `corr_only.py` 对 `883wqwVX` / `KPO1elgN` | 各 180 秒预算耗尽，**双 TIMEOUT** |
| `corr_sweep_once.py` 一次性快扫（每条 1 请求） | `_autologs/corr_ready_0915.txt` **为空**—— 一条"已算好"的都没有 |
| 同期**全量观测**：有没有 429？ | **没有**。全程零 429 → **不是限流封禁** |

**结论**：`200 + Retry-After + 空 body` 的语义**确实是"平台正在现算"、不是故障**（这一点 0915 的修正方向对），
但当前的实情是 **相关计算在账号侧排队积压**，不是 3~4 次轮询就能出。90~180 秒量级都拿不到。

### 8.2 真正的取证入口：提交接口自己会写判决

`POST /alphas/{id}/submit` 会**触发平台现算相关性**，并在 **`GET /alphas/{id}` 的 `is.checks` 里新增一条**
`{"name":"SELF_CORRELATION", ...}`，取值 `PENDING` → `PASS` / `FAIL`。

实测对照：

| alpha | 动作 | `is.checks` 变化 | 终态 | `is.selfCorrelation` |
|---|---|---|---|---|
| `akLp3pzW`（w122_a，0.5 降权版） | 提交 POST | 出现并转 PASS | **ACTIVE / stage=OS** | **0.8036** |
| `883wqwVX`（w122_b，0.35 降权版） | 提交 POST | 出现，**8 分钟仍 PENDING** | 仍 UNSUBMITTED | 无 |

**所以**：
- 想拿 corr 数值 → 提交后读 `GET /alphas/{id}` 的 **`is.selfCorrelation`**（成功入池的会有值）；
- 想拿"能不能过"的判决 → 盯 **`is.checks` 里的 `SELF_CORRELATION`**（`PENDING/PASS/FAIL`）；
- ⛔ **不要再靠 `correlations/self` 反复打**：一条候选动辄上百次请求，纯粹加剧本已积压的相关计算队列
  （0915 本轮实测：探针 ~102 次 + corr_only ~276 次，之后就一直是 PENDING）。

### 8.3 w122「共享腿降权」实战结果（0915）

| 变体 | id | S / F / tS | 降权系数 | 结果 |
|---|---|---|---|---|
| w122_a | `akLp3pzW` | 2.78 / 2.22 / 2.46 | **0.5** | 已提交，实测 **corr = 0.8036**，走**豁免**过（不是直通） |
| w122_b | `883wqwVX` | 2.63 / 2.24 / 2.24 | 0.35 | 提交触发，SELF_CORRELATION 8 分钟 PENDING，未出终态 |
| w122_c | `KPO1elgN` | 2.48 / 2.15 / 2.03 | 0.25 | 未触发（按"一次只提一个"纪律停手） |

**判读**：降权 **0.5 不足以把 corr 压到 0.70 以下**（0.8036）。w85_a 当年靠 0.5 降权从 0.754 降到 0.6803 能直通，
这次同一手法只到 0.8036 —— 说明**降权本身不是普适杠杆**，效果取决于共享腿在 PNL 里的实际占比。
a 之所以仍能入池，靠的是**豁免**（S=2.78 ≥ 1.10 × 热对手 S≈2.53），边距极薄。
⚠️ a 入池后，b/c/k 等同骨架兄弟的 corr 会被立刻顶高 → **按第二节"相关性是动态的"，b/c/k 的旧判断全部作废**。

**下一步方向**：降权继续往下压（0.35/0.25）已在本轮触发但未出判决；
真破墙仍要回到**换更冷的锚**（`src/mine/mine_batch123.py`：fundamental2 里 alphaCount≈0 的字段）。
