## ⚠️ 术语译法对照（量化语境 · 动手背之前先看这一节）

BRAIN 官方文档大量使用比喻性、平台专有词汇，**按字面直译会出洋相，甚至把含义译反**。下表给出量化/金融场景下的正确译法，标注 ❌ 的是常见直译陷阱。

| 英文 | ❌ 别这样译 | ✅ 量化语境正确译法 | 为什么 |
|---|---|---|---|
| **Pasteurization** | 消毒 / 巴氏消毒 | **池外标的置空（按池过滤）** | 借"巴氏消毒法"比喻**净化数据范围**。实际动作只有一句：把**不在所选 Universe 内**的标的取值设为 NaN，让它不参与计算。本质是**按股票池过滤**，股票当然不需要"消毒" |
| Instrument / Instrument type | 工具 / 工具类型 | **标的 / 标的类型** | instrument 在金融语境指可交易的金融工具，此处即股票 |
| Universe | 宇宙 | **股票池 / 标的池** | 平台预定义的可交易标的集合，如 `US:TOP3000` |
| Sub-universe | 子宇宙 | **子股票池** | 由主池切出的子集（如 TOP3000 → TOP1000） |
| **Book size** | 账本规模 | **账面规模（多空双边名义敞口）** | 默认 2000 万美元；假设本金 1000 万 + 2 倍杠杆，故各项收益率指标以**半仓 1000 万**为基数 |
| **Margin** | 保证金 | **单位成交盈亏（交易效率）** | ⚠️ 此处 `Margin = PnL / 总成交额`，衡量"每交易 1 美元赚多少"（常用 bps 表示），**与"保证金"毫无关系** |
| Long / Short Count | 多/空工具数 | **多头 / 空头持仓标的数** | 日均被做多、做空的股票只数 |
| Region | 地域 | **市场区域** | USA / EUR / ASI / CHN / GLB 等 |
| Lookback Days | 回望天数 | **回溯窗口（天数）** | 决定时序/分组算子回看多少天历史数据（如 252、66） |
| Truncation | 截断 | **单票权重上限（截尾）** | 限制单只标的最大权重，建议 0.05–0.1 |
| Delay | 延迟 | **信号延迟** | 0=当日盘中用当日数据；1=用 T-1 数据次日交易，**防前视偏差（look-ahead bias）** |
| Unit Handling | 单位处理 | **量纲校验** | 检测 `price + volume` 这类量纲不兼容并告警 |
| Test Period | 测试周期 | **验证期** | 与 Train（训练期）对应，从 IS 划出用于验证、防过拟合 |
| **Fitness** | 体能 | **适应度（综合质量分）** | BRAIN 专有综合指标 = Sharpe × √(收益/换手)，**不是通用金融术语** |
| **Spectacular** | 壮观 | **卓越（最高档）** | Alpha 评级最高档，形容业绩优劣，不是形容景观 |
| **Production Correlation** | 生产相关性 | **在产 Alpha 相关性** | 与平台**已上线在产（production = 实盘环境）** 的全部顾问 Alpha 做相关性比对 |
| IS Ladder Sharpe | IS 阶梯夏普 | **IS 分段夏普稳定性** | 把 IS 按时间切成若干段，要求各段 Sharpe 均稳定（不是只某一段好） |
| ACTIVE | 活跃 | **已上线（在产）** | 已提交通过、进入 OS 测试、开始累积 Weight |
| DECOMMISSIONED | 退役 | **已下线** | 数据集停用或 OS 长期表现不佳，被平台停用，不再累积 Weight |
| Operator | 操作符 | **算子**（官方中文称"运算函数"） | 两种叫法都对，考试记住英文即可 |
| Backfill | 回填 | **前值填充（回填）** | 用历史最近有效值填补当前缺失值 |
| Winsorize | 缩尾化 | **缩尾（去极值）** | 把极端值压回均值 ± N 倍标准差的范围内 |
| Vector data | 向量数据 | **向量数据（多条目数据）** | ⚠️ **不是数学意义上的向量**；是"股票 × 日期 × 条目"的三维结构，必须先降维 |
| Matrix data | 矩阵数据 | **矩阵数据（二维面板）** | 股票 × 日期 的二维面板 |
| Entry | 入口 | **条目 / 记录** | 一只股票一天可能有多条记录（如多条新闻、多个客户） |
| Neutralization | — | **中性化（组内去均值）** | 标准量化术语，保留 |
| Turnover / Drawdown / Coverage | — | **换手率 / 最大回撤 / 覆盖度** | 标准量化术语，保留 |
| Alpha | 阿尔法 | **Alpha（因子 / 信号 / 预测表达式）** | 直接保留英文 |

> **一句话记住最容易考的三条**：
> ① Pasteurization = **池外置空**，不是消毒；
> ② Margin = **单位成交盈亏**，不是保证金；
> ③ Production Correlation = **与在产（实盘）Alpha 的相关性**，不是"生产"。

# 第一部分　WorldQuant 与顾问项目

## 1.1 WorldQuant 基本背景（①）

| 项目 | 内容 |
|---|---|
| 成立 | **2007 年** |
| 总部 | 美国康涅狄格州格林威治（Greenwich, CT） |
| 中国分部 | 北京、上海（另含中国香港、中国台湾） |
| 全球规模 | **13 个国家/地区、24 个办公室** |
| BRAIN 平台 | 2021 年启动，全球 **7000+ 名研究顾问** |
| AUM（管理规模） | 接近 **100 亿美元** |

> ⚠️ 注意：AUM 是"近 100 亿"，不要写成"100 亿整"或"千亿"。考试只考大致量级与年份。

## 1.2 Research Consultant（研究顾问）是什么（①③④）

- 开放给所有人的**兼职研究岗**，用平台提供的 **15 万+ 数据、算力、API** 挖掘 Alpha。
- **不是**投资课程、**不是**投资建议服务、**不是**赚快钱通道。
- 报酬 = 提交 Alpha 的**数量 × 质量 × 个人 value factor（等级系数）**；**没有提交就没有收入**。
- 前 3 个月"试用期"收入少；3 个月后提升 level，收入可有几倍到几十倍差异。
- ⚠️ **利益冲突**：当前在金融机构/金融科技公司任职者，可能因利益冲突无法成为兼职顾问。

## 1.3 成为顾问的积分门槛（Challenge Score）（①）

- **自动邀请路径**：Challenge Score 达 **10,000 分（Gold 金牌）** 后次日，通常系统自动邀请（但有风控，并非人人必邀）。
- **国区（中国）额外要求**：除 10,000 分外，还需累计提交 **20 个 Alpha** + 通过 **Alpha 研究能力测试题**（即"零基础学量化"讲座基础知识）。
- 查询路径：`Competitions → Challenge`。

> 计分规则（每日上限 / 按天计分 / 更新时点 / 数量质量两因子）**唯一口径见 1.7**，此处不重复。

## 1.4 顾问 vs 用户 权限区别（①）

| 维度 | 用户（User） | 顾问（Consultant） |
|---|---|---|
| 导航栏颜色 | 蓝色 | 绿色 |
| 数据/地区/功能/算力 | 受限 | 完整 |
| **同时回测 Alpha 数量** | **最多 3 个** | **最多 10 个** |
| 回测周期 | 5 年 | 10 年 |
| 提交测试 | 基础 6 项 | 新增 **在产 Alpha 相关性 + IS 分段夏普稳定性** |
| 可用数据集/市场区域 | 少 | 多（EUR/ASI 等仅顾问） |

> **Region（市场区域）选择规则（一战定生死）**：填**当前合法所在地**不是国籍；香港排队更快但有硬性条件（合法在港证明 + 香港本地银行卡）。越晚改 region 账号被锁风险越大。银行卡姓名必须与问卷一致，不能用家人卡。

## 1.5 顾问工作职责与收入构成（③）

**工作职责（一句话）**：基于平台数据/工具/回测框架做 alpha research，提交符合要求的成果，并对自己的提交负责（不能托管给 AI 机械跑）。

**收入四部分（必背）**

| 收入类型 | 金额范围 | 核心决定因素 |
|---|---|---|
| **Base Payment（日常津贴）** | Regular（常规 Alpha）：1–60 USD/Alpha/天；Super（超级 Alpha）：1–60 USD/天（分别计算） | Value Factor（价值因子）/ Theme（主题任务）/ Quantity Factor（数量因子）/ Self-Growth Factor（自我成长因子） |
| **Quarterly Payment（季度奖金）** | 新人→Expert（专家级）：200–2000；Master（大师级）：2000–8000；最高 25000 USD | Weight Factor（权重因子） + Value Factor（价值因子） + OS 表现（样本外表现） |
| **Competition（比赛奖金）** | 视名次 | 各类比赛/双周评比 |
| **Referral Bonus（推荐奖）** | **200 USD/人** | 被推荐人成为顾问并 ≥10 天提交、保持 1 月+ |

> 关键点：Regular Alpha（常规 Alpha）**每日上限 4 个**，Super Alpha（超级 Alpha）**每日上限 1 个**（累计 100 个 Alpha 解锁）；季度奖需每自然季度 **20 天有提交**；Base 每 2 个月发、Quarterly 每季度末发上季度；税务 800 内免、超 800 部分 20%。新人前 3 月核心目标是**提高 Value Factor（价值因子）**。

## 1.6 平台行为准则（②）

**AI 使用边界**：鼓励用 AI 辅助理解/整理/生成思路，**但不能替代研究责任**——顾问必须理解自己提交的 alpha，不能把账户"托管"给 AI 机械生成提交。

**7 类明确禁止行为（必背）**

1. 通过捷径替代真实研究（索要/私下交换/买卖 alpha、凑分凑提交）
2. 开小号、冒用身份、规避账户规则（**一人一号**）
3. 非法牟利、侵犯平台知识产权（传播/出售/盗用课程、数据、alpha、代码）
4. 成为顾问后对提交不负责（长期交低质量 alpha）
5. 把工作理解为单纯刷脚本（无理解地机械运行）
6. 长期挂机 / 异常活跃 / 浪费算力
7. 违反利益冲突等合规要求

**违规后果**：风控面试 → 账户限制 → 冻结 → 中止合同 → 追究法律责任（按严重程度递增）。

## 1.7 WorldQuant Challenge 挑战赛规则（⑰，考纲附录点名）

**性质**：一项**永久的在线个人比赛**。**新用户自动参加**；排行榜按 **国家 / 大学 / 城市** 三个维度对合格用户排名。

**级别与门槛（必背）**

| 级别 | 分数门槛 | 权益 |
|---|---|---|
| 青铜 | **> 1,000 分** | 入门级 |
| 白银 | **> 5,000 分** | 可访问特别培训课程和视频（Events 页面） |
| **黄金** | **> 10,000 分** | **有资格获得研究顾问（Research Consultant）邀请** |

> ⚠️ 拿到 10,000 分只是**得到邀请资格**，不等于自动成为顾问——还需满足其他条件（如是否为顾问计划所运行国家/地区的居民等）。国区另有"20 个 Alpha + 能力测试"要求（见 1.3）。

**计分机制（高频考点）**

| 规则 | 说明 |
|---|---|
| 计分单位 | 按**天**结算（**平台统一美东时间**：北京 20 号 00:00–11:59 = 美东 19 号），**不是**按每个 Alpha 累加——平台每天给"当天提交过 Alpha 的人"算一个**当日总分（这套积分决定排名与顾问资格，非美元）**，而不是"1 个 Alpha = N 分"逐条相加 |
| 每日上限 | **2,000 分**，通常每天提交 1–2 个 Alpha 即可接近上限 |
| 是否有负分 | **没有**，得分只增不减 |
| 更新时点 | 美东时间**凌晨 3 点**（约北京时间下午 3–4 点） |
| 同分处理 | 得分相同者**排名相同** |
| 依据表现 | 提交 Alpha 的**数量 + 质量**（以 5 年样本内表现为依据） |

**两个因子怎么算**

- **数量因素（Quantity Factor）**：当天提交的 Alpha 越多，该因素越大、得分越高。
- **质量因素（Quality Factor）**：当天所有 Alpha 质量因素的平均值，取决于四项设置与样本内结果：

| 质量因素看什么 | 方向 |
|---|---|
| 股票池（Universe） | **池越小，得分越高** |
| 自相关性（Self Correlation） | **越低越好** |
| Fitness(适应度) | **越高越好** |
| 延迟（Delay） | **D1 的贡献大于 D0**（Delay-1 优于 Delay-0） |

> 两个因素会在"**当天至少提交了 1 个 Alpha 的所有用户**"之间做归一化，最终每日得分 = 归一化数量因素 + 质量因素的函数，上限 2,000。

**Challenge 考点速记**：10,000 分拿资格 · 每日上限 2,000 · 按天计分不按个 · 美东凌晨 3 点更新 · 无负分 · **池越小/D1/低自相关/高 Fitness 得分越高**。

> 与本项目的关联：这四项与 4.2 的提交测试同源——**低自相关 + 高 Fitness + 小池（TOP500 类）+ D1**，既是得分最优，也是你当前"破相关墙"要攻的方向。

# 第二部分　BRAIN 平台基础

## 2.1 Alpha 是什么 + 运行原理（How BRAIN Works）（④）

**Alpha 定义**：一种用**表达式**编写的数学模型，对**不同标的（股票）**分配不同权重（头寸），预期长期盈利。表达式 = **数据字段 + 算子 + 数值**。

**BRAIN 是什么**：基于网络的**全球金融市场回测引擎**，输入 Alpha 表达式，输出 PnL 曲线与各项指标。正权重=多头（盼涨），负权重=空头（盼跌）。

**回测 7 步口诀（超高频）**：

> 算得分 → 去中心（中性化） → 归一化 → 配资金 → 算盈亏（PnL） → 滚动测（每天重复） → 画曲线（累计 PnL）

| 步骤 | 人话 | 具体怎么做（机制，以表达式 `rank(-returns)`、市场中性化、Delay 1 为例） | 目的 |
|---|---|---|---|
| 1 算 Alpha 向量 | 用 T-1 数据给每只股票打分 | 把股票池里**每一只股票**代入表达式各算出一个数。打分逻辑完全由表达式决定：例 `rank(-returns)` = 取 9/26（T-1）当日收益取负后排名，收益最低的股票得最高分、最高的得最低分，`rank` 输出均匀分布在 0~1。每只股票一个数，排成一列 = 当天（T）的 Alpha 向量 | 想法变数字 |
| 2 中性化 | 组内减均值，多空抵消 | 向量里**每个值减去所在分组的平均值**（分组=整个市场 / 行业 / 子行业，由 Neutralization 设置定）。减完全部值之和=0、正数之和=负数之和 ⇒ 做多总金额=做空总金额，整体不再赌大盘涨跌 | 降市场风险 |
| 3 归一化 | 权重绝对值之和=1 | 中性化后的值**逐个除以它们绝对值的总和**。例：绝对值总和 2.3，每个值 ÷2.3，得新向量，绝对值之和=1——这组数就是每只股票的**归一化权重** | 控总仓位规模，不随信号强弱漂移 |
| 4 配资金 | 按权重分 2000 万美元 | **权重 × 2000 万美元账面 = 每只股票的美元头寸**。例：权重 −0.22 → 440 万美元空头；+0.03 → 60 万美元多头。正=买入做多，负=借票卖出做空 | 生成当天目标组合 |
| 5 算单日 PnL | 用次日实际涨跌算盈亏 | 仓位是 T 日建好的（用 T-1 数据），"次日"是相对数据日说的。用 T 日**实际**涨跌算：单日 PnL = Σ(美元头寸 × 当日实际收益率)，全池加总 = 当天总 PnL。走势与预测一致就赚、相反就亏 | 验证预测 |
| 6 滚动每一天 | 历史每天重复 1–5 | 回测区间（IS，约 5 年）里**每个交易日**重复 1–5，每天一组权重 + 当日 PnL。当天实际买卖金额 = 今天权重 − 昨天权重；这笔交易额占组合的比例 = 换手率（报告的是区间日均值） | 完整盈亏序列 |
| 7 累计画曲线 | 每日 PnL 累加 | 每日 PnL 逐日累加成**累计 PnL 曲线**，Sharpe / Fitness / 回撤等指标都从这条曲线上算出来 | 最终 PnL 图 |

> 单日 PnL = Σ(仓位大小 × 当日收益率)；当日收益率 = 今收/昨收 − 1。收益不滚投，亏损注资补回，**账面规模（book size）恒定**。

| 设置 | 作用 | 考试要点 |
|---|---|---|
| Language | 表达式语言 | 目前仅 **Fast Expression** |
| Instrument type | 标的类型 | 仅 **Equity（股票）** |

| **Truncation** | 单票权重上限 | **0≤x≤1**，建议 **0.05–0.1**（单只 5–10%）；0=不限制 |
| **Neutralization** | 中性化 | Market/Industry/Subindustry，组内减均值 |
| Lookback Days | 回溯窗口（天） | 影响部分算子取历史的长度，如 252/66 |
| **Pasteurization** | **池外标的置空（按池过滤）** | 默认 **On**：非 Universe 标的 → NaN |
| **NaN Handling** | 缺失值处理 | 默认 **Off** |
| Unit Handling | 量纲校验 | 检测 price+volume(成交量) 等不兼容量纲并告警 |
| Test Period | 验证期 | 从 IS 划 Train/Test，默认 0 年；**显示验证期后才能提交** |

### Pasteurization 到底在做什么（易误解，必考）

官方借用"巴氏消毒法（pasteurization）"作比喻，意思是**净化数据范围**——**不是给股票消毒**。它的实际动作只有一句：

> 把**不在你所选股票池（Universe）内**的标的，其输入值统一设为 **NaN**，让它们不参与后续计算。

- **Pasteurize = On（默认）**：只保留池内标的有效值。好处：横截面/分组算子（如 `group_rank`）只在池内比较，不会因池外标的混入而口径失真。
- **Pasteurize = Off**：所有可用输入都参与；需要精确控制时可用 `pasteurize(x)` 算子手动指定范围。

**典型用法（对比池内 vs 全市场）**：

```
group_rank(pasteurize(sales_growth), sector) - group_rank(sales_growth, sector)
```

第一个 `group_rank` 只在 **Alpha 股票池（如 TOP500）** 内做行业内排名，第二个在**全市场**做行业内排名，两者相减衡量"池内 vs 全市场"的排名差异。

> 考试说法：Pasteurization = **按股票池过滤（池外置空）**，默认 On，作用是**保证横截面比较的口径一致**。

**NaN Handling 两类行为（易错）**

| 算子类型 | NaNHandling=On | NaNHandling=Off（默认） |
|---|---|---|
| 时间序列（如 `ts_mean`） | 全 NaN → 返回 **0** | 全 NaN → 返回 **NaN** |
| 分组（如 `groupmax`） | 某标的 NaN → 返回**该分组对应值**（组级结果） | 某标的 NaN → 返回 **NaN** |

> 例：`NaNHandling=On` 且某股 `sales` 为 NaN → 返回该行业 `sales` 最大值。

## 2.3 BRAIN Fast Expression 语法结构（⑩⑪）

**核心结论（你已确认）**：Fast Expression **不是编程语言、没有传统语法**。只有三元素：

| 元素 | 是什么 | 示例 |
|---|---|---|
| 数据字段 | 有名字的数据集合 | `close` / `volume` / `sales` |
| 算子（运算函数） | 数学/统计变换函数 | `rank` / `ts_delta` / `group_rank` |
| 数值 | 常量 | `2` / `0.1` / `20` |

**唯一两条"语法规则"**：
- 多行注释用 `/**/`（不是 `#` / `//`）
- 每行结尾加分号 `;`，**最后一行不加**

其余"语法感"均来自算子本身（`volume > adv20 ? A : B` 来自比较+`if_else`；`a = ...;` 是算子链非变量声明）。**复习重点=背熟算子清单，不是学语法。**

## 3.1 数据字段分类、结构差异与注意事项（⑫⑭⑮）

### 按"结构"分三类（核心题型）

| 维度 | 矩阵字段（Matrix） | 分组字段（Group） | 向量字段（Vector） |
|---|---|---|---|
| 形状 | 二维：股票 × 日期 | 一只股票一个整数（组别 ID） | 三维：股票 × 日期 × 条目 |
| 存什么 | 连续数值信号 | 类别标签（归哪一组） | 一组记录（一只股票一天多条） |
| 用法 | 直接当信号 | 作为 `group_*` 第二参数（分桶依据） | **必须先 `vec_*` 降维** |
| 示例 | `close(收盘价)`/`volume(成交量)`/`adv20(过去20天日均成交量)` | `sector(行业大类)`/`industry(行业)`/`subindustry(子行业)`/`market(市场)` | `rlv_*(关系向量字段)`/`etv_*(预估向量字段)` |

**关键注意事项**

1. **分组字段不进 Alpha 当信号**，只喂 `group_*` 算子当分桶依据。字段存的是**整数类别编号**（`sector` 有 4 类 → 值为 0/1/2/3；从 0 开始排），**编号是任意分配的，不含大小/顺序/倍数含义**，所以严禁 `sector > 1`、`rank(x) * sector` 这类算术——那是把标签当数字用。
2. **向量字段必须降维**：`vec_avg` / `vec_sum` / `vec_count` 把三维压成二维才能进 Expression；且**仅 Python 模式**可用（Expression 模式不行）。无效值可能返回 NAN/-1/-2147483648，需过滤。
3. **data field ≠ dataset**：field 是一张表（CSV，命名 unique），dataset 是装表的文件夹；回测框里填 **field 名**不是 dataset 名。
4. **矩阵字段坑**：注意 `delay` 的盘中语义（delay 0 下 close 是收盘前近似价，部分数据盘中无值）、缺失值处理。

### 按"内容"分 6 大类（⑭）

| 类别 | 频率 | 核心用途 | 典型字段 |
|---|---|---|---|
| 价量 PV（价格与成交量） | 日频 | 动量/反转/流动性 | close(收盘价), vwap(成交量加权均价), adv20(过去20天日均成交量) |
| 基本面 | 季/年（最快季） | 价值/盈利/质量 | ebit(息税前利润)/ev(企业价值), roa(总资产收益率), liabilities(总负债)/assets(总资产) |
| 分析师 | 季/年 | 预期修正/惊喜 | est_eps(预期每股收益), etz_eps_delta(分析师EPS预期调整值) |
| 情绪 | 日频 | 市场情绪 | snt_bullish(看涨情绪), snt_buzz(情绪热度/讨论声量) |
| 新闻 | 事件 | 事件驱动 | news_return_5min(新闻发布后5分钟收益率) |
| 关系 | 低频 | 供应链/竞争 | customers(客户/大客户), competitors(竞争对手) |

> 财务三张表 = 资产负债表 / 利润表 / 现金流量表。价量字段已对公司行为（拆股/股息）**复权调整**，**不可直接用原始价**。

| 6 分布形状 | `X < scale_down(datafield) && scale_down(...) < Y` | `X < scale_down(cashflow_op) && scale_down(cashflow_op) < Y` | 归一化后分段画直方图。**官方原文只规定 X/Y 在 0~1 之间自取，没有给具体数字；实操就是切 0~0.25/0.25~0.5/… 分段跑，把每段 Long 数拼成直方图 |

## 3.2.1 6 招在 BRAIN 平台上的实操步骤（手把手）

这 6 招不是 Alpha，是"探针"——目标**不追求 Sharpe**，而是用 **Long/Short Count（多头/空头持仓标的数）** 数出字段的属性。按下面 5 步走（路径来自官方 first-alpha 与 simulation-results 页）：

**第 1 步：进 Simulate（模拟）页**
顶部 `Alphas(阿尔法)` 下拉标签 → 选 `Simulate(模拟)` 子标签 → 点右上角**齿轮图标**打开 Settings（设置）面板。（官方原文：*Alphas are created and simulated on the Simulate page in the Alphas dropdown tab; click on the gear icon at the top right-hand side corner*）

**第 2 步：设 Settings（设置）**

| 设置项 | 探针要填的值 | 为什么 |
|---|---|---|
| Region(地区) | `US: TOP3000`（你账号有权限的） | 决定字段清单与股票池 |
| Universe(股票池) | `TOP3000` | 覆盖度分母 = 3000 |
| Delay(延迟) | `1` | 探针不影响，保持默认 |
| Decay(衰减) | `0` | 探针要原始值，不衰减 |
| Neutralization(中性化) | `NULL(无)` | **关键**：中性化会按行业/市场加工字段，改掉原始值就测不准覆盖度/分布 |
| Pasteurization(巴氏平滑) | `OFF(关)` | 同样避免加工原始值 |
| Truncation(截尾) | `0` 或保持 | 探针不截断 |
| Language(语言) | `FASTEXPR` | 用 Fast Expression 语法 |

> 来源分层：官方 6 招原文只强制两项——**Neutralization=None、Decay=0**（`docs/study/learn/docs/05_understanding-data/01_data.md`："Simulate the below expressions in 'None' neutralization and decay 0 setting"）；表中其余行（Delay=1 默认、Pasteurization=OFF、Truncation=0）是**保障"读到原始值"的实操配置**，其中"中性化必须 NULL 否则 Long Count 只有个位数"来自 2026-09-24 本项目实测（见下方踩坑注）。另注：官方 first-alpha 示例做真 Alpha 时用 Neutralization=MARKET/Subindustry、Pasteurization=ON，那是优化信号用的；探针必须改回 NULL/OFF。

**第 3 步：粘贴表达式**
把上方 338–345 表"具体写法"列的表达式复制进 Alpha 表达式输入框。探覆盖度贴 `cashflow_op`；探更新频率贴 `ts_std_dev(cashflow_op, 66) != 0 ? 1 : 0`。

**第 4 步：点 Simulate（模拟）**
跑完默认显示 Cumulative PnL（累计盈亏）图和 Sharpe 图——**探针不用看这些**（裸字段/掩码跑出的曲线没意义）。

**第 5 步：读 Long/Short Count（多头/空头持仓标的数）**
切到 **Stats（统计）标签** → 滚动到 **IS Summary（样本内摘要）** 块，里面有一行 `Long/Short Count`（官方原文：*The number of instruments in long or short positions, respectively*）。这就是你要的数。

**怎么把 Count 翻译成结论（以 `cashflow_op(经营现金流)` 为例）：**
- **覆盖度**（表达式 `cashflow_op`）：Long=正值标的、Short=负值标的。现金流基本都正 → Short≈0，Long≈有数据的标的数。覆盖度 = (Long+Short)/Universe。若 Long=2850、Universe=3000 → 覆盖度 95%。
- **非零量**（表达式 `cashflow_op != 0 ? 1 : 0`）：Long=非零标的数（有效样本），Short=恰好为 0 的。Short=0 说明该字段无零值；Short 很大说明很多股票该字段=0（信号稀疏）。
- **更新频率**（表达式 `ts_std_dev(cashflow_op, 66) != 0 ? 1 : 0`）：Long=这 66 天里有波动的标的（即期间更新过财报的）。Long 远小于 Universe=季度更新特征；Long 接近 Universe=日频更新。
- **取值范围 / 中位数 / 分布**：同理用 Long 数占 Universe 的比例判断阈值落在多少股票上。

> ⚠️ **实测踩坑（2026-09-24）**：跑 `cashflow_op != 0 ? 1 : 0` 时如果**忘了把 Neutralization(中性化) 设成 NULL(无)**，Long Count 只有个位数（实测 0~9）、Short Count 0~1，看起来像"没数据"。原因：0/1 掩码是常数信号，默认中性化会**在每个分组内去均值**——一组内全是 1 的话去均值后全变 0，权重清零，只剩极少数不均匀的组有持仓。**看到 Count 个位数，先回 Settings 检查 Neutralization 是不是 NULL**，改完重跑，Long 会跳到 ≈非零标的数（两千多）。另外掩码输出只有 0 和 1（永不为负），所以 Short≈0 是正常的，别当成异常。顶部挂着 Excellent/Needs Improvement 标签是对真 Alpha 的提示，对探针无意义不用管。

> 一句话：探针 = "把想问的属性变成 是/否 问题 → 用 Long/Short Count 数有多少只股票答 是"。平台不报 Sharpe，只报 Count。

## 3.3 数据探索表达式：用途 → 用到的算子（考纲单列条目）

考纲要求"了解几种常用的**数据探索表达式及其用途**"。第 3.2 节给了 6 个探针（表达式唯一出处），这里把它们**拆到算子层**——考试里可能被换成"用什么算子实现"，认得出才不慌。

| 想探什么 | 用到的算子 | 算子所属类别 | 这个算子在干什么 |
|---|---|---|---|
| **覆盖度** | 裸字段（无算子） | — | 直接看有值的标的数 |
| **非零有效量** | `!=`、`? :`（=`if_else`） | **Logical** | 比较返回 0/1 掩码，把连续值转成"是/否" |
| **更新频率** | `ts_std_dev`、`!=`、`if_else` | **Time Series** + Logical | 过去 66 天（季）有没有波动 → 变过就是更新过 |
| **取值范围** | `abs`、`>` | **Arithmetic** + Logical | 取绝对值探量级，二分开阈值 |
| **历史中心值** | `ts_median`、`>` | **Time Series** + Logical | 过去 1000 天的中位数（官方口径 over 5 years） |
| **分布形状** | `scale_down`、`&&`(`and`)、`<` | **Transformational** + Logical | 类 MinMaxScaler 压到 [0,1] 后分段看分布 |

**这一节的用法**：考试若问"**怎么用算子检查一个字段的覆盖度/更新频率**"，把 3.2 的表与本表对照答。

## 3.4 操作符七大类与目的（⑩，超高频）

官方共 **7 大类 60 算子**（base 级；Expert/Master/Grandmaster 另有高级算子）：

| 类别 | 数量 | 做什么操作/变换 | 代表算子 | 达到什么目的 | 频率 |
|---|---|---|---|---|---|
| **Arithmetic 算术** | 14 | 四则、幂、对数、开方、符号、绝对值 | `add` `subtract` `divide` `power` `signed_power` `log` `sqrt` `abs` `sign` `inverse` `reverse` `max` `min` | 把原始字段**换算成有经济含义的比率/量级**（如 EPS/价格、取对数压右偏） | 中 |
| **Logical 逻辑** | 10 | 比较、与或非、条件选择、缺失标记 | `if_else`（=`? :`）`and` `or` `not` `is_nan` `<` `<=` `==` `>=` `!=` | 把连续值**转成 0/1 掩码或做条件分支**，是事件型 Alpha 的骨架 | 中（`? :` 高频） |
| **Time Series 时序** | 23 | 对**单只标的过去 d 天**做统计/变换 | `ts_mean` `ts_delta` `ts_std_dev` `ts_rank` `ts_zscore` `ts_sum` `ts_corr` `ts_delay` `ts_backfill` `ts_decay_linear` `hump` `kth_element` `ts_arg_max` `days_from_last_change` | 捕捉**时间维度上的变化**（动量/反转/波动/回填缺失），降换手也靠这一类 | **最高** |
| **Cross Sectional 横截面** | 5 | 对**当天全部标的**横向比较 | `rank` `zscore` `normalize` `quantile` `winsorize` | **消除量纲**、去极值、化成分位——写 Alpha 收尾用 | **最高** |
| **Vector 向量** | 2 | 把三维向量数据降成二维矩阵 | `vec_avg` `vec_sum` | **让向量字段能进 Expression**（否则报错），是使用高级关系/预估数据的前置步骤 | 低（考概念） |
| **Transformational 变换** | 2 | 自定义分组、条件交易 | `bucket` `trade_when` | `bucket` 造**自定义分桶**喂 `group_*`；`trade_when` **控制交易时机、降换手** | 中（`trade_when`） |
| **Group 分组** | 5 | 在**组内**做统计/排名 | `group_rank` `group_neutralize` `group_mean` `group_zscore` `group_scale` | 实现**行业内中性化/组内比较**，消除行业差异只比同业相对强弱 | 高 |

> **一句话串起来**：时序（纵向、单股看历史）和横截面（横向、当天看全市场）是两大主力；算术/逻辑是配料；分组做横向的"分组版"；变换和向量是特殊场景（降换手、降维）。

**必背易混对比**

| 易混 | 区别 |
|---|---|
| `rank` / `group_rank` / `ts_rank` | 全市场排名 / 组内排名 / 时序排名 |
| `sum` / `ts_sum` | 截面求和（当天多只标的）/ 时序求和（单只标的过去 d 天）|
| `zscore` / `ts_zscore` / `group_zscore` | 截面 / 时序 / 组内 |
| `normalize` / `ts_scale` | 横截面去均值 / 时序缩放至 0~1 |

**高频防坑**

1. `divide`/`inverse` 遇 0 **报错** → 加极小量（epsilon）：`divide(x, add(y, 0.0001))`
2. `power` 非整数 y **丢符号** → 用 `signed_power`
3. `winsorize`（缩尾）的 std：默认 4，取值 2~5；**std 越大剔除的极端值越少**
4. 向量字段必须 `vec_avg`/`vec_sum` 降维
5. `trade_when(条件, 满足时的值, 否则的值)`；否则传 `-1`/`NaN` 可平仓/空仓
6. 代码用了 `group_neutralize` → 面板 Neutralization 选 **None**

**各思路首选算子**：反转 `-ts_delta(close,d)+rank`；动量 `ts_mean`；价值 `group_rank(eps/close, subindustry)`；降换手 `ts_decay_linear`/`hump`/`trade_when`；覆盖度不足 `kth_element`/`ts_backfill`（前值填充）；事件 `ts_zscore`+`trade_when`；去极值 `winsorize`/`quantile`/`rank`。

- **26 个"其他"家族**：模型类最多（基本面评分、SmartRatios、EPS/收入/EBITDA 估计、价格动量、信用/风险等），另含内幕、空头持仓、期权、系统性风险、波动率。

# 第四部分　理解回测结果与提交

## 4.1 回测指标定义 / 计算 / 衡量什么（⑥）

**评级面板（Fitness 适应度评级）**

| 评级 | Fitness (Delay 1) | Fitness (Delay 0) |
|---|---|---|
| Spectacular **卓越** | > 2.5 | > 3.25 |
| Excellent 优秀 | > 2.0 | > 2.6 |
| Good 良好 | > 1.5 | > 1.95 |
| Average 平均 | > 1.0 | > 1.3 |
| Needs Improvement 待改进 | ≤ 1.0 | ≤ 1.3 |

> Delay 0 阈值更高（信息更及时、理应更难），同等级 D0 门槛约为 D1 的 **1.3 倍**。

> ⚠️ **易混点：为什么"至少 Average"后面跟的是数字？**
> **Fitness 本身是一个连续数值**（由公式算出，如 1.42），平台再按数值区间给它**贴一个等级标签**。两者是同一件事的两种表示，就像"90 分 = 优秀"：
> - 面板上你看到的是**文字**：Average / Excellent / Spectacular
> - 判定依据的是**数值**：跨过哪一档门槛，就贴哪一档标签
> - 所以"Fitness 至少 Average" = **数值必须过 Average 档门槛**：Delay 0 > 1.3，或 Delay 1 > 1.0
> - 反过来：`需要改进（Needs Improvement）` = D0 ≤ 1.3 或 D1 ≤ 1.0，即**没过最低档**，不可提交

**核心公式（必背）**

```
Return      = 年化 PnL / (book size / 2)          // 账面规模2000万，半仓1000万为基数，2倍杠杆
IR          = mean(PnL) / stdev(PnL)
Sharpe      = sqrt(252) × IR ≈ 15.8 × IR
Fitness     = Sharpe × sqrt( abs(Returns) / max(Turnover, 0.125) )
Turnover    = 成交金额 / book size                  // 衡量交易频率
Margin      = PnL / 总成交额                        // 单位成交盈亏（交易效率），非保证金
Drawdown    = (PnL 最高点−最低点) / (0.5 × BookSize) // 以半仓归一化的最大回撤
```

**IS Summary 指标含义速查**

| 指标 | 含义 | 衡量什么 | 好方向 |
|---|---|---|---|
| Long / Short Count | 每日**多头 / 空头持仓标的数** | 组合**分散度与覆盖度**：能做多/做空的股票够不够多 | 越多越分散（同时要两边均衡） |
| Sharpe | IR × √252 | **单位波动换来的收益**——风险调整后表现 | 越高越好 |
| Fitness | 上式（适应度/综合质量分） | 把收益、波动、换手**揉成一个综合分** | 越高越好 |
| Returns | 年化 PnL / (book size 账面规模 / 2)，百分比 | **赚钱能力**（年化收益率，以半仓为基数） | 越高越好 |
| Turnover | 成交额 / 账面规模 | **调仓频率**：每天为维持仓位买卖多少 | 越低越好 |
| Margin | **单位成交盈亏**（PnL / 总成交额，常用 bps） | **交易效率**：每成交 1 美元赚多少（扣成本前） | 越高越好；高换手时尤其要够高 |
| PnL | 美元盈亏 | **绝对赚钱多少**（当日/累计） | 累计曲线向上、平稳 |
| Drawdown | 最大回撤 % | **最坏情况有多坏**——抗风险能力 | 越小越好 |

> **指标之间的关系（理解性考点）**：`Sharpe = √252 × mean(PnL)/stdev(PnL)`——IR 年化而来，所以 BRAIN 里**没有独立的 IR 字段**。`Fitness` 同时惩罚高换手、奖励高收益，是"综合质量分"。**好 Alpha = 高 Sharpe + 高 Return + 低 Turnover + 小 Drawdown**，四者常互相拉扯（提收益往往升换手），所以要平衡而非单项拉满。

> Self Correlation（自相关性）目的：确保 Alpha 集合足够**分散化**，避免重复提交（最高相关性≈1 说明高度冗余）。

## 4.2 Alpha 提交标准与各项测试（⑦）

**提交流程**：Simulate → UNSUBMITTED（未提交）→ Submit Alpha → 通过 6 项测试 → OS 测试 → **ACTIVE（已上线在产）**。

**6 项测试（必背阈值）**

| 测试 | 阈值 | 提升方法 |
|---|---|---|
| **Fitness** | D0 > 1.3，D1 > 1.0（至少 Average） | 提 Sharpe/Returns，降 Turnover |
| **Sharpe** | D0 > 2.0，D1 > 1.25 | 提收益一致性、降波动 |
| **Turnover** | **1% < T < 70%** | decay / hump / trade_when |
| **权重集中度测试** | 单只标的最大权重 **< 10%** | rank / truncation（设权重上限）/ ts_backfill |
| **子股票池测试** | 子池 Sharpe 须高于**至少一个**阈值。**T1/T2 双阈值公式出自实拍考卷截图（`docs/exam/images/exam_subuniverse_threshold.png`，卷面原文照录）**：`T1 = 0.75 × √250 × max(0.065, √((Universe_size/Subuniverse_size)×N))`；`T2 = 0.75 × 原Sharpe / (Universe_size/Subuniverse_size)`，两阈值随子池规模动态降低（详解见真题专区第 2 题）。⚠️ 注意：官方 Learn 归档文档（`docs/study/learn/docs/04_interpret-results/03_how-pass-sub-universe-test.md`）给的是**单阈值**公式 `subuniverse_sharpe ≥ 0.75 × √(subuniverse_size/alpha_universe_size) × alpha_sharpe`（含算例 0.75×√(1000/3000)×2.73=1.18）——两处项目内来源并存且形式不同，考试按卷面 T1/T2 答，机制理解（"子池越小门槛越低"）两版一致 | 避免市值乘数、按流动性分别衰减、提整体 Sharpe |
| **自相关性测试** | PnL 相关 **< 0.7**，或 Sharpe 高 10% | 换思路/换数据集，提高分散化 |

#### 为什么要分这三类？（理解用意，别死记）

三个类型本质是**三把不同的尺子**，量完全不同的东西，且各自挂钩一项实际利益：

| 类型 | 量的维度 | 平台用意 | 挂钩利益 |
|---|---|---|---|
| **ATOM** | **纯度**（只用 1 个数据集） | 信号来源最干净、最容易归因；给新手降低门槛（跳过分段稳定性测试） | **ATOM 专项比赛**（要求 single dataset，GLB / USA D1 下提交） |
| **Pyramid** | **广度**（区域×延迟×数据类别） | 逼你别窝在单一市场/数据源刷数量，要真扩面 | **顾问等级硬指标**（见下表） |
| **Power Pool** | **独立度**（自标种子，互相关 ≤0.5） | 平台买的是**互不相关的收益流**，不是重复微调 | **Uniqueness（独特性）评分**——平台排名三维之一 |

**顾问等级对金字塔数量的硬要求**（来源：`docs/project/目标_排名目标.md`「wq-guide 数据」+ `docs/project/SDD_methodology_48轮实测沉淀.md` §5，两处项目内文档独立记载一致）：

| 等级 | Signals/季 | **Pyramids/季** | Combined Perf |
|---|---|---|---|
| Expert | ≥20 | **≥10** | >0.5 |
| Master | ≥120 | **≥30** | >1.0 |
| Grand Master | ≥220 | **≥60** | >2.0 |

> 三列人话：**Signals/季 = 每季度提交（过审入池）的 Alpha 数量下限**（Expert 20 个≈每月 7 个）；**Pyramids/季 = 每季度新点亮的金字塔格子数**（一格 = 一个"区域 × 延迟 × 数据类别"新组合的首个 Alpha，考覆盖广度）；**Combined Perf = 顾问季度综合表现分门槛**（衡量质量：IS/OS 一致、低相关的收益流——项目内归档只给了门槛数值，没有它的计算公式）。注：此表来自 wq-guide 抓取（原文档已散佚），项目内 `目标_排名目标.md` 与 `SDD_methodology_48轮实测沉淀.md` 两处数字一致互为佐证；这是**顾问等级的季度维持/晋升要求**，不是 10,000 分的邀请门槛。

> **关键理解**：100 个高度相关的 Alpha，组合起来风险并不比 1 个低；10 个低相关的才真正降低风险。所以平台从三个角度卡你——来源是否干净（ATOM）、覆盖是否够广（Pyramid）、是否真的互相独立（Power Pool）。三者共同服务一个目标：**可组合、可归因、低相关的 Alpha 库**。

> **为什么金字塔要限"最多 2 格"**：如果允许一个 Alpha 占 N 格，你刷一个大杂烩就能顶 N 个，覆盖度就被"虚高"了。限制 2 格是**反作弊设计**——想扩面，就得老老实实做不同的 Alpha。

**特殊 Alpha 类型**

**先分清：三个类型里只有 1 个是你自己标的**

| | **ATOM** | **Pyramid（金字塔）** | **Power Pool** |
|---|---|---|---|
| **谁判定** | **平台自动** | **平台自动** | **你自己勾选** |
| 依据 | 数你用了几个数据集字段 | 数区域×延迟×类别落在几个组合 | 你自己标记哪几个当"种子" |
| 你能不能标 | 不能，也没得标 | 不能，也没得标 | ✅ 只有这个是主动动作 |

- **ATOM**：仅用 1 个数据集字段；**跳过 IS 分段夏普稳定性测试**，仍需常规 IS + 2Y Sharpe。分组字段不破坏 ATOM 资格（官方原文共 9 类：currency/country/exchange/sector/industry/subindustry/market/split/adjfactor，出处 `docs/study/learn/docs/04_interpret-results/01_alpha-submission.md`）。
- **Pyramid（金字塔）**：市场区域 + 信号延迟 + 数据集类别**三样齐全**才构成 1 个金字塔（缺一不成塔）；**最多贡献 2 个金字塔**。
  - ⚠️ **别误读**：限制的是"**塔的个数 ≤ 2**"，不是"三个维度里挑两个"。同一区域同一延迟下用了 2 个不同数据类别 → 落在 2 个格子 → 2 个塔（刚好达标）；用 3 个类别 → 3 个塔 → 超限失资格。
- **Power Pool**：Sharpe≥1.0、唯一算子≤8、唯一数据字段（不含分组）≤3、换手 1%–70%、自相关≤0.5、USA D1。
  - ⚠️ **标记不可逆**：一旦标为 Power Pool，**即使之后取消标记，它也永久留在自相关性池里**——手别抖。
  - ⚠️ **对比范围**：只与你**自己的** Alpha 算相关性，不与平台上所有 Alpha 比。
  - ⚠️ **标了不加钱**：顾问收入四部分（Base Payment 日常津贴 / Quarterly Payment 季度奖金 / Competition 比赛奖金 / Referral 推荐奖）里**没有 Power Pool 这一项**。真正与收入挂钩的是 **Quality Factor**——"表现越好、地区和 universe 越分散、**相关性越低**，Quality 越高"，那是靠**做出**低相关 Alpha 挣来的，不是点标记点出来的。
  - ⚠️ **别全标**：Pool 内部要**两两** ≤ 0.5（比常规自相关 0.7 更严）。标 n 个就要满足 `n(n-1)/2` 对——2 个 1 对、5 个 10 对、10 个 45 对，**按平方增长**。全标必然出现 >0.5 的对而违规，且标错退不出来 → 稳妥做法是**少标、精标**，只挑真正独立且硬的少数几个。

#### 先认字：数据类别 / 区域 / 延迟的英文都是啥

看到 `USA-D1-analyst` 这种写法别懵，拆开就是三个标签。英文对照如下：

| 英文 | 中文 | 是什么数据 |
|---|---|---|
| **pv**（Price Volume） | 价量行情 | 开高低收、成交量、vwap、adv20、returns |
| **fundamental** | 基本面财报 | 财务三张表：资产 / 利润 / 现金流量（如 `sales(营收)`、`assets(总资产)`） |
| **analyst**（Analyst Estimate 分析师预估） | 分析师预估 | 券商分析师对未来 EPS / 营收的预测（如 `est_eps(预期每股收益)`、`etz_eps_delta(分析师EPS预期调整值)`） |
| **news** | 新闻 | 新闻前后价格/成交量的变动（不是文本情绪本身） |
| **model** | 模型 | 平台预处理的衍生特征（字段少但被用得多，价值评分高） |
| **option** | 期权 | 期权相关指标 |
| **socialmedia** | 社交媒体 | 社媒情绪 |

> **平台类别就是这 7 个**（Data Explorer 类别筛选器原文，见真题专区第 4 题截图）。
> ⚠️ 教程里讲的"情绪（sentiment）、关系（relationship）"是**教学分类**，平台类别筛选器里**没有**这两个独立类别——别把它们当格子点。

| 缩写 | 中文 | 含义 |
|---|---|---|
| **USA / EUR / CHN / GLB / ASI** | 美国 / 欧洲 / 中国 / 全球 / 亚洲 | **市场区域** |
| **D0 / D1**（Delay 0 / 1） | 延迟 0 / 延迟 1 | D0 = 当日数据当日交易；D1 = 次日开盘交易 |

#### 两把尺子粗细不同（ATOM 与金字塔的核心区别）

**最容易绕错的一点：ATOM 和金字塔数的是两种不同粒度的东西，不要混为一谈。**

| | **ATOM** | **金字塔（Pyramid）** |
|---|---|---|
| 数什么 | **数据字段**的个数（细粒度） | **数据集类别格子**的个数（粗粒度） |
| 上限 | = **1** 个 | ≤ **2** 个 |
| 判定依据 | 表达式里出现几个不同数据集的字段 | 区域 × 延迟 × 类别，落在几个组合里 |

**三个例子（USA + D1 固定，只变数据）：**

| 表达式 | 字段数 | 类别数 | ATOM？ | 几个塔 |
|---|---|---|---|---|
| `etz_eps` | 1 | 1（analyst） | ✅ 是 | 1 个 ✅ |
| `etz_eps + etz_revenue_delta` | 2 | **1**（同属 analyst） | ❌ 否 | **仍是 1 个** ✅ |
| `etz_eps + sales` | 2 | 2（analyst + fundamental） | ❌ 否 | 2 个 ✅ 刚好到顶 |

> **关键**：两把尺子**各自独立判定**。中间那行既不是 ATOM（字段超 1），却仍只占 1 个塔（类别没超）——两个结论互不冲突。

**"类别格子"到底是什么、能选哪几个？**

- **格子 = 一个完整的「区域 × 延迟 × 类别」组合**（如 `USA-D1-analyst`）。你的 Alpha 落在几个这样的组合里，就是贡献了几个塔；数的是**格子的个数**，不是字段个数——同一个类别用了 10 个字段，也只点亮 1 个格子。
- **可点的类别就是平台那 7 个**：`pv`（价量）、`fundamental`（基本面）、`analyst`（分析师预估）、`news`（新闻）、`model`（模型）、`option`（期权）、`socialmedia`（社媒）——任选。教程里的 sentiment（情绪）、relationship（关系）是教学分类，平台类别筛选器里没有，**不算格子**。
- **规则只看个数 ≤ 2，不规定选哪两个**：`pv + analyst`、`analyst + news`、`fundamental + model` 全都可以。⚠️ 但点亮 **3 个及以上**就当场失去金字塔资格。
- **换区域或换延迟同样会开出新格子**：`USA-D1-analyst` + `USA-D0-analyst` = 2 个塔；再加 `EUR-D1-analyst` = 3 个 → 超限。

#### ATOM 规则详解（高频坑点）

**坑 1：分组字段"不参与计算"——不是不用，是"不占名额"**

`货币 / 国家 / 交易所 / 行业 / 产业 / 子行业 / 市场 / 拆股 / 复权因子`（currency / country / exchange / sector / industry / subindustry / market / split / adjfactor）**共 9 类**照常参与表达式运算，只是在统计"你用了几个数据集字段"时**不计入配额**（官方 9 类清单见 `docs/study/learn/docs/04_interpret-results/01_alpha-submission.md`；Power Pool 段的 7 类分组清单见 `docs/exam/Alpha提交测试完整清单.md`——两份文档口径并存，ATOM 计数以官方 9 类为准）。

> 类比：考试规定"最多带 1 本教材"，字典不算教材名额——你照样翻字典，但字典不占那 1 本。

| 表达式 | 计数 | 是否 ATOM |
|---|---|---|
| `group_rank(-ts_rank(close,5), industry)` | close(pv1) = 1；industry 不计 | ✅ 是 |
| `group_rank(sales, sector)` | sales(fundamental6) = 1；sector 不计 | ✅ 是 |
| `rank(close) + rank(sales)` | pv1 + fundamental6 = **2** | ❌ 否 |

**为什么要排除**：分组字段是**类别标签**（回答"归哪组"），不是预测信号（不回答"值多少"），本身不携带 alpha 信息。规则把名额留给真正的信号源。

**坑 2：`inst_pnl` 会让 Alpha 多占一个数据集（pv1）**

- **pv1（第1个价量数据集）** = Price Volume 家族的**第 1 个价量数据集**——就是最基础那套每日行情：`open（开盘价） / high（最高价） / low（最低价） / close（收盘价） / volume（成交量） / vwap（成交量加权均价） / adv20（过去20天日均成交量） / returns（日收益率）`（`pvN` 即第 N 个价量数据集，如 pv13、pv17 为含向量数据的高级价量集）。
- **`inst_pnl`** = **单个标的（instrument）的每日盈亏**。虽然写法像算子，但平台把它**计作使用了 pv1 数据集**——因为算盈亏必须用价格，价格来自 pv1。
- 后果：`inst_pnl(<来自非 pv1 数据集的字段>)` 会被算成 **2 个数据集**（pv1 + 该字段所属数据集）→ **失去 ATOM 资格**。

**坑 3：常规 IS / 2Y Sharpe / IS Ladder Sharpe 三个词别混**

| 测试 | 查的是什么 | 时间范围 | ATOM |
|---|---|---|---|
| **常规 IS 测试** | 6 项基础阈值（Fitness / Sharpe / Turnover / Weight / 子池 / 自相关） | 整个 IS 样本内期 | 必须过 |
| **2Y Sharpe 测试** | 最近 **2 年**的 Sharpe 是否达标 | **Semi-OS（半样本外）**最近 2 年（隐藏段） | 必须过 |
| **IS Ladder Sharpe（IS 分段夏普稳定性）** | 把 IS 期切成若干段，**每段 Sharpe 都稳定**，防止只在某一段行情好 | IS 期内分段 | **跳过** |

> 记忆口诀：**ATOM = 少懒一项（跳过分段稳定性），但常规六项和最近 2 年照查。**

> Power Pool 的完整门槛与三个坑（标记不可逆 / 只与自己比 / 别全标）见上方「特殊 Alpha 类型」段。

## 4.3 提交筛选标准 + Do/Don't（第四课）（⑨）

**好 Alpha 四特征（必背）**：**Robustness（稳健性）/ Uniqueness（独特性）/ Value-add（增量价值）/ Consistency（一致性）**。稳定亏钱也比暴涨暴跌强——基金经理更敢投稳定曲线。

**❌ Don'ts（反面教材）**

1. **Overfitting（过拟合）**：硬塞无意义参数，如 `ts_rank(mdf_vol^2.124 * ..., 600)`（2.124 无意义）。
2. **Adding Noise（加噪音）**：为降相关性加无逻辑表达式，如 `... *0.65 + rank(...)`（0.65 是无意义缩放，样本外必崩）。

**✅ Do's（好实践）**：多尝试 datasets/市场区域/参数/子股票池；读官方 Learn 材料；保持开放心态；**复现后往前走一两步（换 dataset / group / operator）**。

> Decay 修正认知：是对 **中性化之后的仓位权重**做时间加权平均（非原始信号）；Alpha 表达式参数通常最大 5 天，decay 设 10/20 在金融意义上不成立（信号被稀释）。
> ⚠️ 口径澄清："最大 5 天"是第四课的**教学经验值（原话带"通常"），不是平台硬限制**——设置里 decay 可以填很大，只是大了信号被平均稀释、S 掉。它针对的是**短周期动量/反转信号的参数**；长窗口算子（探针 `ts_std_dev(x,66)`、`ts_median(x,1000)`、财报类 252 天）天然用长回看，不受此约束。实操例外：本项目挖矿实测 **decay=8** 有效（降 TO 提 F、降相关 0.03+，见 SDD §8.4）——decay 是 S↔TO 跷跷板，停在拐点即可，没有"必须 ≤5"。

## 4.4 IS / OS / TEST（④⑥，考纲单列条目）

**为什么要切三段**：如果只用一段历史回测，你可以不停调参把它调到"完美"，但这种完美是**背答案**，换个时间段就失效（过拟合）。所以平台把历史切成"你能看的"和"你看不到的"，用后者检验真实水平。

```
        ┌──────────── IS（样本内，你能看到）────────────┬───── 你看不到 ─────┐
        │                                               │                    │
  ...───┴───────────────┬───────────────────────────────┼───────┬────────────┴──►
                   TEST / 验证期                    Semi-OS    Real OS      今天
                 (从 IS 里划出，防过拟合)          (最近 2 年)  (提交后至今)
```

| 区间 | 长度 | 你能看到吗 | 用途 |
|---|---|---|---|
| **IS（样本内 In-Sample）** | 约 **5 年**（顾问 10 年） | ✅ 回测可见 | 观察表现、调优；**IS 期滚动**——始于约 7 年前、止于约 2 年前 |
| **TEST / 验证期** | 从 IS 划出 | ✅ 可见 | 模拟"样本外"检验，**必须显示验证期后才能提交**（Simulation Settings 里的 Test Period） |
| **Semi-OS（半样本外）** | 最近 **2 年** | ❌ 隐藏 | 平台内部**评分/测试**用（如 2Y Sharpe 测试） |
| **Real OS（真实样本外）** | 提交后至今 | ❌ 隐藏 | 提交后 Alpha 在真实市场的表现，决定长期价值 |

**具体年窗示例**（教程口径，会随时间滚动）：IS = 2016-02 ~ 2021-01；OS = 2021-02 ~ 2023-01。

**关键结论**：
- **提交前你看不到 OS**；提交后平台才跑 OS 测试——所以"IS 很漂亮"不等于能过。
- **同时通过 IS 和 OS 的才叫稳健 Alpha（robust alpha）**。
- **提交后要看的是 Semi-OS 和 Real OS，不是 IS**——这是常见错误认知（拿到 IS 高分就以为稳了）。

> **易混辨析**：`TEST（验证期）` 是**你自己在设置里开启的**、从 IS 内部划出来的防过拟合手段；`Semi-OS / Real OS` 是**平台隐藏的真实未来数据**，你控制不了。前者防你在 IS 里过拟合，后者检验你到底有没有真本事。

## 4.5 进阶（顾问新测试 + 改进方法论）（⑧，加分项）

**顾问新增两项测试**

| 测试 | 通过条件 |
|---|---|
| **在产 Alpha 相关性**（Production Correlation） | 与顾问池任意在产 Alpha 最大相关 < 0.7；或对每个相关性 >0.7 的 Alpha，你的 Sharpe 至少高 10% |
| **IS 分段夏普稳定性**（IS Ladder Sharpe） | 不同时间段上 Sharpe 均稳定，不是只在某一段表现好 |

**Alpha 改进方向**

- **提 Sharpe**：↑Return（更多信息，如 News/Analyst 数据集）或 ↓Volatility（做中性化）。
- **降相关性**：换字段 / 换算子 / 换分组（优先等价替换，不硬造无金融含义的分组）。
- **降换手**：`trade_when(事件条件, Alpha, -1)` 事件框架；`decay`/`hump`/`ts_decay_linear`。
- **降 PnL 波动**：缺失值跳变 → `backfill` 前值填充；信号变化太快 → 加 `decay`；单只标的权重过大 → 设权重上限 Truncation<0.1。
- **防过拟合（官方 8 条技巧 + 三层稳健性测试）**：
  - **① 经济逻辑兜底（最重要、面试必答）**：因子必须有经济逻辑（economic rationale）——能讲清"为什么这个因子该赚钱"，有经济学机理的信号不是对历史的噪声拟合，OS 才能活。官方原文（`learn/docs/04_interpret-results/01_alpha-submission.md`）："有经济学根基的机制（economically grounded mechanism），而不是特定国家的过拟合（country-specific overfitting）"。
  - **② 三层稳健性测试**（出处 `docs/study/Alpha改进与顾问进阶指南.md`）：**Rank test** 把 Alpha 转成排名（抹掉数值大小只留顺序）、**Binary test** 转成 -1/+1（连大小都不要，只留方向）、**Sub/Super universe test** 换到子池/超池重跑——逻辑是**逐层剥掉信息**：每剥一层（数值大小→顺序→只剩方向）后照样赚钱，说明信号在"结构"里而不是在精心调出来的数值刻度里，过拟合的微调就现形了。
  - **③ 官方 8 条技巧**：不把权重集中在高波动股票上；降低因子暴露；不选"最好"的参数（第二好通常过拟合倾向更小）；不为了通过测试而拟合测试；不纠结"选择"（4 还是 6 天犹豫就用 5 或取平均）；不陷"Excellent/Superior"陷阱（IS 好不是重点，能持续才是）；善待他人分享想法；用 Simulation Settings 的 **Test Period** 把 IS 分成 Train/Test，Train 开发、Test 验证。

**D0 Alpha**：盘中用当日数据、收盘前交易，仅 USA/EUR/CHN，能捕捉**隔夜收益**，换手更高因而需要更高 Sharpe/Return 覆盖成本，提交门槛更高。

## 真题 1：回撤（Drawdown）是什么？怎么计算？

![回撤真题](docs/exam/images/exam_drawdown.png)

**标准答案**：

回撤指**一段给定期间内模拟 PnL 的最大减少幅度**，以百分比表示：

```
Drawdown = DollarAmountOfLargestPeakToTroughGapInPnL / (0.5 × BookSize)
```

- **分子**：累计 PnL 从最高点（Peak）到最低点（Trough）的最大美元落差。
- **分母**：`0.5 × BookSize`（半仓）。BRAIN 默认账面规模 2000 万美元，多空对冲下实际敞口约为账面规模一半，用它归一化便于不同 Alpha 间比较。
- **算例**：账面规模 2000 万，PnL 从最高点回落 50 万 → `500,000 / 10,000,000 = 5%`。（衡量什么：见 4.1 IS Summary 表 Drawdown 行）

**易错点**：分母是**半仓**不是全部账面规模；它不是"亏了多少美元"，而是"最大落差相对半仓的百分比"。

## 真题 2：子股票池夏普比率测试的阈值是什么？

![子股票池阈值真题](docs/exam/images/exam_subuniverse_threshold.png)

**标准答案**：

平台把股票池切成子集，检查 Alpha 不是只在少数股票上碰运气。难点：**子股票池夏普比率未超过最低标准**——子池 Sharpe 必须高于**至少一个**阈值，且两个阈值会随子股票池子规模而降低（子池越小门槛越低）。

**T1/T2 公式的出处就是本题截图本身**（`docs/exam/images/exam_subuniverse_threshold.png`，卷面原文照录）——这不是从官方 Learn 文档抄来的：官方 Learn 归档文档（`docs/study/learn/docs/04_interpret-results/03_how-pass-sub-universe-test.md`）给的另一种**单阈值**表述是 `subuniverse_sharpe ≥ 0.75 × √(subuniverse_size/alpha_universe_size) × alpha_sharpe`。备考时以卷面 T1/T2 为准（4.2 六项测试表已并列两版口径）：

- **T1**：基础门槛，含 `√250`（≈250 个交易日的年化因子）、常数下限 0.065、原池/子池规模比。
- **T2**：按原 Alpha Sharpe 等比缩放，子池越接近原池规模，要求越接近原 Sharpe。

**不达标怎么办**：扩大 Universe（如选 TOP3000）、加中性化避免行业集中、让信号在各 sector/industry 都有覆盖、避免市值乘数、按流动性分别衰减。

**易错点**：不是"子池 Sharpe ≥ 原 Sharpe"——子池股票少噪声大，门槛是动态降低的；但也**不能无限低**（T1 的 0.065 下限 + 0.75×√250 系数兜底）。

## 真题 3：拿到一个新数据字段，如何快速理解它？（6 招）

![6招探索真题](docs/exam/images/exam_six_tips.png)

**标准答案**：

官方 **6 招**，表达式、前提设置（Neutralization=None、Decay=0）、读数规则（结果>0 做多、<0 做空）**唯一出处见 §3.2 表 + §3.2.1 实操**。逐字翻译版（考试可用更口语的讲法）：

| 招 | 读成人话（逐字翻译） |
|---|---|
| 1 覆盖度 | 把这个字段的**原值直接丢出去**（可正可负；没值算 0） |
| 2 非零量 | 这字段**不等于 0 吗**？是→给 1，否→给 0 |
| 3 更新频率 | **过去 N 天内**这字段有波动吗（标准差≠0）？是→给 1 |
| 4 取值范围 | 这字段的**绝对值大于 X 吗**？ |
| 5 历史中间值 | **过去 1000 天**的中位数大于 X 吗？（官方原文 over 5 years） |
| 6 分布形状 | 归一化后的值**既大于 X、又小于 Y** 吗？ |

> ⚠️ **`? 1 : 0` 是冗余写法，去掉效果完全相同**：比较算子（`!=` / `>` / `<`）本身就已经返回 1 或 0。所以第 4、5、6 条都没写 `? :` 也照样工作——第 2、3 条写出来只是官方为了让读者看得更明白，两种写法是同一件事。
>
> ⚠️ **为什么非要绕成"0/1"**：平台只暴露两个数字——多头持仓数（Long Count）和空头持仓数（Short Count）。想知道"有多少只股票满足某条件"，就必须先把问题变成"是/否"：满足→1（计入多头），不满足→0（两边都不计），然后数多头有多少只。**第 1 条是唯一例外**：它输出原值而非 0/1，所以多头和空头**都要数**，加起来才是有值的股票数。

**实战演练（以 `sales` 营收字段、TOP3000 池为例）**

| 步骤 | 回测框里实际填 | 读什么数 | 假设读到 |
|---|---|---|---|
| 1 | `sales` | Long+Short | 2300 → 覆盖度 2300/3000 ≈ **77%** |
| 2 | `sales != 0 ? 1 : 0` | Long | 2280 → 日均 2280 只有值；Short=0 说明**无负值** |
| 3 | `ts_std_dev(sales, 66) != 0 ? 1 : 0` | Long | 很高 → 66 天内变过 = 至少**季度更新** |
| 4 | `abs(sales) > 1000` | Long | 2100 → 绝大多数营收 > 1000（单位可能是百万） |
| 5 | `ts_median(sales, 1000) > 500` | Long | 1500 → 约一半股票 5 年窗口中位数 > 500，**中位数在 500 附近** |
| 6 | `0.5 < scale_down(sales) && scale_down(sales) < 0.75`（0.5/0.75 为演示值，官方只规定 X/Y 在 0~1 间自取） | Long | 分段跑完可拼出直方图 → 看**分布是否右偏** |

## 真题 4：Data Explorer 数据类别筛选里的指标怎么看？

![DataExplorer类别真题](docs/exam/images/exam_dataexplorer_categories.png)

**标准答案**：

弹窗六列：**Categories / Regions / Datasets / Fields / Alphas / Value score**——各列含义与 Model（价值分 7 最高）/ Price Volume（分仅 2，内卷）的解读**唯一出处见 §3.2**；7 个平台数据类别的英文对照见 4.2「先认字」表。

## 真题 5：Data Explorer 中衡量数据字段 / 数据集「拥挤度」的指标是？

![拥挤度真题](docs/exam/images/exam_0910_crowding.jpg)

**标准答案：Alpha 数量与用户数量** ✅

**为什么**：
- Data Explorer 里每个字段/数据集都带两个"被使用程度"计数——**平台已有多少个 Alpha 用过它（Alpha 数量）**、**多少个用户用过它（用户数量）**。这两个数越高，说明该字段已被反复开采，就是"拥挤"：你再用它，做出来的 Alpha 大概率与别人高度相关，自相关测试难过、独特性低。
- 其余三个选项都是**评价一个 Alpha 表现好坏**的指标，跟"字段拥挤不拥挤"无关：
  - Turnover 换手率 —— 衡量交易频率，Alpha 层指标
  - Drawdown 回撤 —— 衡量 PnL 曲线最大跌幅，Alpha 层指标
  - Sharpe 与 Fitness —— 风险调整后表现，Alpha 层指标

**考试速记**：**拥挤度 = 有多少人已经用过了**（Alpha 数量 + 用户数量，越多越挤）。三个"表现类"指标（Turnover / Drawdown / Sharpe·Fitness）都是 Alpha 自己的成绩，不是字段的热度。

**实战延伸**：选字段时优先挑 `alphaCount` 低的冷门字段（如 < 200），既降低撞车概率、又拉高 Uniqueness（独特性）——这与本项目"用冷门锚 + 价量腿双轮换破相关性墙"的策略一致。

## 真题 6：使用 `group_neutralize(x, industry)` 且面板 Neutralization 设为 "None"，等效于？

![group_neutralize真题](docs/exam/images/exam_0910_group_neutralize.jpg)

**标准答案：在模拟设置中使用 Industry 中性化** ✅

**为什么**：`group_neutralize(x, group)` 的动作是"**组内每个值减去组均值**"——这跟 Simulation 设置面板里选同等级别的 Neutralization，是**同一件事的两种写法**：
- 用**代码算子**：`group_neutralize(x, industry)`，此时面板必须选 **Neutralization = None**（否则中性化做两遍）
- 用**面板设置**：Neutralization 选 **Industry**，代码里就不用再写

所以两者等价，且此时面板应配 `Neutralization = None, Decay = 0, Truncation = 0` 以保持"原汁原味"。

**排除其他选项**：
- ❌ "会导致模拟报错" —— 不会，这是官方推荐的两种等效用法之一
- ❌ "比面板 Industry 中性化效果更差" —— 效果**完全等价**，谈不上更差，只是代码算子更灵活（可自定义分组、按 sector 或自造 `bucket()` 分组）
- ❌ `group_zscore(x, industry)` —— **这是另一个算子**：zscore 是"减均值再除标准差"（标准化，保留组内相对强弱量纲），neutralize 只是"减均值"（中性化）。两者不同，不能划等号。

**考试速记**：`group_neutralize` ⇄ 面板 Neutralization，**代码用了算子，面板就选 None**；别和 `group_zscore` 混。

## 真题 7：以下哪种做法有助于降低 Alpha 的过拟合风险？

![过拟合真题](docs/exam/images/exam_0910_overfitting_mcq.jpg)

**标准答案：基于经济学 / 金融学逻辑构建 Alpha，而非纯粹的数据挖掘** ✅

**为什么**：
- 过拟合 = 把历史数据里的**噪声**当成可重复的**信号**。有经济/金融逻辑支撑的 Alpha（比如"估值便宜 + 盈利质量好"），其预测力来自可解释的市场机理，换到样本外、换到别的市场仍有理由成立，稳健性强。
- 纯数据挖掘（`ts_rank(mdf_vol^2.124 * ...)` 硬塞 2.124 这种参数去擦边过门槛）没有机理支撑，只是恰好拟合了这段历史，一到 OS 段就崩。

**其余三个选项为什么错**（它们全都会**加重**过拟合）：
- ❌ **只使用价格数据** —— 用不用基本面数据与过拟合无关；价量反而是最拥挤、最内卷的一类，这么限反而缩窄思路。
- ❌ **缩短 IS 期以减少数据量** —— **反了**：样本越少，越容易被噪声主导、越容易过拟合；减少数据只会让结论更不稳。
- ❌ **在 IS 期内不断优化参数** —— **这正是在制造过拟合**：反复拿 IS 表现调参数，等于把噪声也调进模型，是教科书级的过拟合做法。

**考试速记**：**逻辑驱动 = 抗过拟合；数据挖到底、样本越砍越短、参数越调越"好看" = 全是过拟合加速器。**

## 第一部分　WorldQuant 与顾问项目

**问 1：平台为什么要求顾问必须自己理解提交的 Alpha，不能交给 AI 机械生成？**

- **例子/风险**：机械生成的 Alpha 你答不出逻辑，风控面试就穿帮；且多为过拟合、OS 表现差。

**问 2：顾问的收入由哪几部分构成？其中的高低由什么决定？**

- **要点**：四部分——Base（日常津贴）/ Quarterly（季度奖金）/ Competition（比赛奖金）/ Referral（推荐奖）；各部分金额、决定因子、发放节奏**唯一出处见 §1.5 两张表**。

**问 3：顾问与普通用户在权限上有哪些主要区别？**

- **要点**：五点——同时回测数、回测周期、可用区域/数据集、提交测试多两项、导航栏颜色，**见 §1.4 表**。

## 第二部分　BRAIN 平台基础

**问 4：请描述 BRAIN 回测一个 Alpha 的完整流程。**

- **要点（7 步）**：口诀「算得分 → 去中心 → 归一化 → 配资金 → 算盈亏 → 滚动测 → 画曲线」，每步人话与目的**见 §2.1 表**。
- **易错**：收益不滚投，**账面规模恒定**。

**问 5：Pasteurization（池外置空）是做什么的？为什么会引起误解？**

- **要点**：把不在所选股票池内的标的置为 NaN、默认开启；机制与典型用法**见 §2.2 详解**。
- **易混**：它是**按池过滤**，不是去极值——去极值是 `winsorize`。

**问 6：NaN Handling 开启时，时间序列算子与分组算子处理缺失值的方式有何不同？为什么这么设计？**

- **要点**：两种行为对照**见 §2.2 NaN 表**。
- **为什么**：分组函数是"一组共用一个值"，个别成员缺失不该污染整组，用**组内有效股票的组级统计值兜底**；时序是"逐日一列值"，全缺才兜底为 0。

**问 7：BRAIN Fast Expression 支持哪些语法结构？**

- **要点**：不是传统编程语言，三要素（数据字段 + 算子 + 数值）与唯一两条规则**见 §2.3**。复习重点 = 背熟算子清单，不是学语法。

## 第三部分　数据探索与操作符

**问 8：数据字段按结构分为哪几类？各类在使用时有哪些注意事项？**

- **要点**：矩阵 / 分组 / 向量三类的形状、用法、示例与四条注意事项**唯一出处见 §3.1**（分组字段只喂 `group_*`、向量必须 `vec_*` 降维且仅 Python 模式、field ≠ dataset）。

**问 9：拿到一个新数据字段，如何快速评估它的覆盖度、更新频率和取值范围？**

- **要点**：官方 **6 招探针**——6 条表达式唯一出处见 §3.2 表，实操与踩坑见 §3.2.1，算子归类见 §3.3。
- **为什么关中性化和 decay**：探针要的是原始属性，中性化/平滑会"加工"数据，数出来就不准了。

**问 10：Data Explorer 里的 Value score 说明什么？为什么 Model 类评分高、Price Volume 类评分低？**

- **要点**：Value score（1–10）= 该类别**还有多少未挖掘的 Alpha 潜力**，不看字段多少；Model 分高 / PV 分低的具体数字与解读**见 §3.2**。

**问 11：时间序列算子与横截面算子有什么区别？各举一例说明用途。**

- **要点**：时序 = 单只标的的历史 d 天（纵向，如 `ts_mean(close,20)` 动量/反转/波动）；横截面 = 当天全部标的横向比较（如 `rank(close)` 消量纲、化分位）。易混三兄弟（`zscore`/`ts_zscore`/`group_zscore`）见 §3.4。

**问 12：`group_neutralize(x, industry)` 和 `group_zscore(x, industry)` 有什么区别？**

- **要点**：一个只**减均值**（等价面板 Neutralization=Industry，代码用了它面板必须选 None），一个**减均值再除标准差**（组内标准化）。完整推演与选项排除见**真题 6**。

## 第四部分　理解回测结果与提交

**问 13：什么是换手率（Turnover）？它如何影响 Fitness？如何降低？**

- **要点**：Turnover = 成交额/账面规模，衡量调仓频率；在 Fitness 公式里**换手越高 Fitness 被压得越低**（公式与指标含义见 §4.1；注意公式里 0.125 是下限保护，低于它不再额外惩罚）。
- **降法**：Decay / `ts_decay_linear` / `hump` / `trade_when`（详见 §4.5）。

**问 14：一个 Alpha 提交前要通过哪些测试？各自的通过条件是什么？**

- **要点**：6 项测试阈值**唯一出处见 §4.2 表**（Fitness / Sharpe / Turnover / 权重集中度 / 子股票池 / 自相关）；顾问另加两项见 §4.5。

**问 15：什么是过拟合？如何降低过拟合风险？**

- **要点**：过拟合 = 把历史**噪声**当可重复**信号**，IS 漂亮 OS 崩。防法 8 条见 §4.5；经济逻辑为什么抗过拟合、错误选项排除见**真题 7**。

**问 16：IS / OS / TEST 分别是什么？为什么要有 OS？提交后看哪一段？**

- **要点**：四段划分（IS / TEST / Semi-OS / Real OS）、时间轴与"提交后看 Semi-OS 和 Real OS"的结论**唯一出处见 §4.4**。核心一句：只用 IS 可以不停调参"背答案"，OS 是看不到的检验段。

**问 17：ATOM、Pyramid（金字塔）、Power Pool 分别是什么？计数口径有何不同？**

- **要点**：ATOM 数**字段**（=1）、Pyramid 数**类别格子**（≤2）、Power Pool 自己勾选（两两 ≤0.5）——完整门槛、例子与坑点**唯一出处见 §4.2**（含 `inst_pnl` 占 pv1、标记不可逆两个高频坑）。

**问 18：平台为什么要区分这三类特殊 Alpha？**

- **要点**：三把尺子——纯度 / 广度 / 独立度，平台买的是**互不相关的收益流**；挂钩利益（比赛 / 顾问等级 / Uniqueness 独特性）见 §4.2。

**问 19（附：Challenge 补充）：WorldQuant Challenge 的计分规则是什么？为什么"股票池越小、D1 比 D0"得分更高？**

- **要点**：计分规则（按天计分、上限 2000、无负分、美东凌晨 3 点、级别门槛）**唯一出处见 §1.7**。
