# Alpha Production Loop

把「一个经济机制」变成「一条可提交的 Alpha」的标准化流程。适用于任何 agent（不绑定仓库路径）。
本文件只放**跨项目成立**的方法论与判据；本仓库的具体命令见 `references/repo-workflow.md`。

## 何时使用

- 需要连续产出可提交 Alpha（每日配额制）
- Alpha 指标不达标，需要判断「是 idea 错、形态错、还是池子挤」
- 需要设计超级 Alpha（组合已提交件）
- 需要沉淀/更新判据库

## 核心模型：四层判据

诊断任何一条 Alpha，按这四层从下往上查，**不要跳层**。

| 层 | 问题 | 判断依据 | 常见误判 |
|---|---|---|---|
| L1 数据层 | 字段是否承载这个机制 | S 低 + 换手极低(<0.03) → 字段不承载机制 | 把"浅构造结果"当数据判死证据 |
| L2 形态层 | 表达形式是否匹配数据性质 | 流量类保水平值；改历史位置常破坏信号 | 以为"算子越多越强" |
| L3 参数层 | 窗口/decay/截断 | 影响量级小（实测 ≤0.01 量级） | 花几十轮扫参数 |
| L4 池层 | 与已提交池的相关性 | PROD/SELF 只有提交才知道（部分接口可预检） | 把本地预估当硬门 |

**结论顺序**：先定位到层，再只在该层动手。L3 通常不是杠杆。

## 主流程

1. **一个 idea**：一句话说清"在赌什么"（谁、因为什么、会怎样）。
   说不清就不许进队列。
2. **机制 → 字段**：选字段前必须查平台字段接口确认存在与语义（`description` 不能只看名字）。
3. **构造**：必须有「字段间关系」（比值/差/条件）且变换层数 ≥2；
   禁止"多个字段各自归一化后直接相加"。
4. **模拟**：一次一条，串行。记录 S / F / 换手 / 子池 / 2Y / FAIL 项。
5. **诊断**：按四层判据定位；改形状，不在同一条上取负号蒙。
6. **提交**：指标全过才 POST；403 判决书是唯一真值。
7. **记账**：每轮一行（表达式、设置、指标、FAIL、本轮修正动作）。

## 形态知识（可迁移，均有样本量）

- **同向乘法 > 各自归一化后相加**：同族多腿相乘是"多证据确认"，加腿常同时抬 S 与子池指标（实测 S 2.20→2.38）。
- **低覆盖字段不能当乘数**：覆盖 0.47 的字段做乘数会把一半标的归零，S 从 2.2 崩到 1.09。
- **风险调整形态**（水平 ÷ 自身波动）能显著改变与池内的相关性，是拉低 SELF 的有效手段（实测 SELF 0.97→0.60）。
- **外壳语义有排序**：有界 min-max 类外壳在"指标已贴门槛"时可作最后一刀；差距大时无效（实测 0.7020→过线 vs 0.8943→0.90）。
- **换分母要换到"不含量级成分"的分母**（如流动负债），混回账面权益即退化。

## 相关性知识（最贵的墙）

- 新件的 SELF 主要由**主腿**决定：换辅助腿/换窗口只动 ≤0.006，换主腿才动。
- **同一内核的外壳变体只能交 1 条**：4 个变体实测 SELF 0.89 / 0.95 / 0.98。
- **PROD 的载体是信号形态，不是数据集**：换数据集只能小幅下降（实测 0.90→0.81），同形态仍撞。
- 强信号与"池内不拥挤"通常互斥：拥挤是因为它有用。

### ★ 算子频次 ≠ 相关性（n=15 实测，反直觉）

| SELF 区间 | 平均字段重叠度 | 平均算子重叠度 |
|---|---|---|
| ≥0.70（撞线，n=5） | 0.23 | 0.85 |
| <0.70（通过，n=10） | 0.40 | 0.75 |

极端反例：算子重叠 1.00、字段重叠 1.00 的件 SELF 0.3277；算子重叠同为 1.00 的件 SELF 0.9743。

**结论：算子集中不是相关性的原因。** 相关性的真正驱动是「主腿是否度量同一个经济量」——
把 `sales` 换成 `revenue`（字面不同、经济量相同）→ SELF 0.9743。

因此监控对象应是三件事，而不是算子频次：
1. **主腿经济量的重复**（同一经济量每天只允许一个主腿件）；
2. 平台 **CLUSTER_TEST**（策略簇集中度，官方量化；>1.58 为 WARNING，不拦但须记录）；
3. 提交时的 **SELF 实测**（唯一真值，本地不可预检）。

字段侧的集中度可以直接统计（台账 245 条表达式）：180 种字段里 Top5 占 35.6%，
单一字段最高 72 次。这才是"批次不均衡"的真实来源。
- 超级 Alpha = 已提交件的组合，其 SELF ≈ 组件对池内件的平均相关 ⇒ **池子演进会让同一个配方从能过变成过不了**。

## 反模式（每一条都对应真实事故）

1. 用模板批量生成候选，再用结果给数据集判死刑。
2. 为了满足本地门而拼表达式（形状倒推 idea）。
3. 单一场景失败就宣布机制被证伪。
4. 把算子个数当复杂度（实测与 S 无单调关系）。
5. 死磕已是池内地板的参数（decay/trunc/中性化对 PROD 常为零影响）。
6. 未核实字段语义就用（同名不同义，如 Net Cash ≠ 现金及等价物）。
7. **带着 A 级 WARNING 去提交**：`CLUSTER_TEST` <1.58 会被平台明确判"does not qualify"，
   等于白占一次提交机会。（`MATCHES_THEMES` / `OSMOSIS_ALLOCATION` 属 B 级，不影响提交。）

## 提交前检查清单（A 级全 PASS 才发）

| 级别 | 项 | 通过线 | 备注 |
|---|---|---|---|
| A | LOW_SHARPE | ≥1.58 | 平台硬门 |
| A | LOW_FITNESS | ≥1.0 | 平台硬门 |
| A | HIGH_TURNOVER | ≤0.7 | |
| A | LOW_SUB_UNIVERSE_SHARPE | 随 S 浮动 | 差 0.01 也要继续改形态 |
| A | LOW_2Y_SHARPE | ≥1.58 | |
| A | CONCENTRATED_WEIGHT | PASS | |
| A | **CLUSTER_TEST** | **≥1.58（PASS）** | **WARNING 即不合格**（资格门） |
| A | SELF_CORRELATION | ≤0.70 | 只有提交才知道 |
| A | PROD_CORRELATION | ≤0.70 | S≥2.1 可触发高 S 宽限 |
| B | MATCHES_THEMES / OSMOSIS_ALLOCATION | 不阻断 | 影响主题乘数与渗透排名；EUR 件通常必然 WARNING，记录即可 |

**CLUSTER 的实证规律**：与 S 大致正相关但不单调（加腿可能降：1.52→1.46、1.51→1.36）；
现实提升手段是换对的轻腿（FCF 加流动比率 1.52→1.67）与提 S（S≥2.1 常落 1.6+）。

## 自动更新协议（AI 每次会话结束前必做）

1. 跑 `scripts/sync_evidence.py` 重新生成判据快照；**不要手改快照**。
2. 若本轮出现**新判据**：先写入事实源（台账/知识库），再让脚本提炼；
   禁止只改 SKILL.md 而不留事实依据。
3. 若某条旧判据被推翻：在 `CHANGELOG.md` 追加 `[REFUTED] 旧结论 → 新证据（文件/数值/样本量）`。
4. 机制类结论只能来自 `verified` 的经验条目，并保留来源。
5. SKILL.md 只写"可迁移结论"；所有仓库路径/命令写进 `references/repo-workflow.md`。
